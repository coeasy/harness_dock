# HarnessDock v0.2.0 五轮架构重构最终方案

> 状态：**v0.2.0 最新且唯一有效的架构设计基线**  
> 日期：2026-09-03  
> 原则：不兼容旧 Host Core、Host Bridge v1、隐藏控制页、Electron、历史 v0.2.x 过渡逻辑；参考 `dsh-tauri-desk/deepseek-harness-desktop` 只吸收经过验证的设计经验，不复制其 Service/Workflow、状态模型、IPC 或产品 UI。

---

# 0. 最终产品定义

HarnessDock v0.2.0 定义为：

**DeepSeek Harness 的跨平台 Native Host Kernel + Managed Runtime Platform。**

它不是新的 Harness UI，也不是一个把所有 Runtime 内容都塞进安装包的“Full Client”。

它只负责六类基础能力：

1. **Host**：Tauri 原生窗口、系统集成、更新和安全边界；
2. **Runtime**：可信 Node/dsh Runtime Image 的获取、验证、激活、运行、回滚；
3. **Lifecycle**：Actor、Lease、Desired State、Reconciler；
4. **Surface**：Harness Web 主界面以及按需 Recovery/Gateway/Diagnostics；
5. **Remote**：Native Gateway 与移动端安全会话；
6. **Verification**：协议、状态机、体积、性能、发布链全部机器验证。

正常桌面主链只有一条：

```text
Tauri Host
  -> Host Kernel
  -> Runtime Image Store
  -> RuntimeActor
  -> RuntimeLease
  -> SurfaceActor
  -> Harness Web
  -> optional Shell Extension
```

首次无 Runtime 时：

```text
Tauri Host
  -> Bootstrap Surface
  -> Runtime Registry
  -> Download/Verify Runtime Layers
  -> Atomic Activate
  -> RuntimeActor
  -> Harness Web
```

移动端主链：

```text
Mobile Tauri
  -> HTTPS Gateway
  -> authenticated session
  -> Native GatewayActor
  -> RuntimeLease
  -> Harness Runtime
```

任何 Shell、Tray、Gateway 管理、Diagnostics、Update UI 都不能成为健康 Harness Web 正常启动的前置依赖。

# 1. 参考项目给出的最重要启示

参考项目最新桌面安装包已经证明：

- Windows NSIS 可以约 6 MB；
- macOS DMG 可以约 9~10 MB；
- Linux DEB 可以约 12 MB；
- Linux AppImage 因携带更多系统库仍约 90 MB。

真正原因不是特别激进的 Rust 编译，而是：

```text
Host Installer != Node + dsh Runtime
```

Node 和 dsh 在首次运行时下载，dsh Core 还可以独立升级。

HarnessDock 借鉴这个**分发边界**，但升级成更严格的：

**Host Installer + Signed Layered Runtime Store + optional Offline Full Bundle。**

详细事实分析见：

`docs/reference/deepseek-harness-desktop-size-and-feature-analysis.md`

# 2. 新的分发架构

## 2.1 默认安装器只发布 Host

默认 Host Installer 只包含：

```text
Native Tauri binary
Host Protocol schema / generated SDK
Bootstrap/Recovery/Gateway/Diagnostics minimal frontend
minimal Shell integration assets
trust root / runtime registry metadata
Tauri updater
icons / installer metadata
```

不包含：

- Node Runtime；
- 完整 dsh Core；
- 第三方社区插件；
- workspace 根 node_modules；
- build/test/docs 开发依赖。

## 2.2 可选 Offline Full Bundle

另行发布：

```text
HarnessDock Offline Bundle
  Host Installer
  Runtime Image Manifest
  Node Layer
  DSH Layer
  Integration Layer
```

离线 Bundle 用于：

- 企业离线环境；
- 无网首装；
- 灾备；
- 自动化兼容性验证。

普通用户不再为离线能力被迫每次下载完整 Runtime。

## 2.3 体积目标

CI 建立预算：

| 产物 | v0.2.0 预算 |
| --- | ---: |
| Windows NSIS | <= 15 MB |
| Windows MSI | <= 20 MB |
| macOS DMG | <= 20 MB |
| Linux DEB | <= 25 MB |
| Linux AppImage | <= 100 MB |
| Host Integration Layer | <= 10 MB |
| 单个 Runtime Image compressed | <= 100 MB |

预算是阻止回归的门禁，不是要求为了数字牺牲功能。

# 3. Layered Runtime Image Store

这是新版 v0.2.0 最大架构升级。

不再把 Runtime 理解为一个随 Host 打包的目录，而是内容寻址的层：

```text
Runtime Store
  manifests/
    <image-id>.json
  layers/
    node/<digest>/
    dsh/<digest>/
    integration/<digest>/
  images/
    <image-id>/
  pointers/
    active.json
    previous.json
    candidate.json
  downloads/
    <digest>.partial
  staging/
    <transaction-id>/
```

## 3.1 Runtime Image Manifest

```text
RuntimeImageManifest {
  schemaVersion,
  imageId,
  platform,
  arch,
  hostProtocolRange,
  minHostVersion,
  maxHostVersion,
  nodeVersion,
  dshVersion,
  dshCommit,
  integrationVersion,
  layers[],
  createdAt,
  buildCommit,
  signature,
}
```

每个 Layer：

```text
RuntimeLayer {
  kind: Node | Dsh | Integration,
  digest,
  compressedSize,
  unpackedSize,
  urls[],
}
```

## 3.2 为什么分层

例如：

```text
Image A = Node N1 + DSH D1 + Integration I1
Image B = Node N1 + DSH D2 + Integration I1
```

A -> B 只下载 D2。

收益：

- Host 更新不再下载 Node/dsh；
- dsh 更新不重复下载 Node；
- Integration 不变时不重复下载；
- rollback 只切 image pointer；
- 多 Runtime 版本共享相同 layer；
- 清理可以按引用关系执行。

# 4. Runtime Registry

v0.2.0 不需要立即建设中心化服务器。

Registry 可以先基于 GitHub Release/static manifest：

```text
stable.json
beta.json
runtime/<platform>/<arch>/<image-id>.json
```

Host 的信任模型不是“相信下载 URL”，而是：

```text
embedded trust root
  -> verify channel manifest signature
  -> verify image manifest signature
  -> verify layer digest
  -> verify image compatibility
  -> atomic activate
```

镜像 CDN/代理只是 Transport Provider，不是 Trust Provider。

---

# 5. Download Engine

借鉴参考项目的成熟下载体验，但升级抽象。

必须支持：

- HTTP Range 断点续传；
- 每源重试 + backoff；
- 多 source fallback；
- Content-Length 未知时安全进度；
- SHA-256 digest；
- manifest signature；
- 下载大小上限；
- 解压文件数量/路径安全限制；
- staging；
- atomic activation；
- cancellation；
- bounded temporary storage。

下载状态由 Host Event 推送：

```text
RuntimeResolveStarted
RuntimeLayerDownloadStarted
RuntimeLayerProgress
RuntimeLayerRetry
RuntimeSourceChanged
RuntimeLayerVerified
RuntimeImageAssembled
RuntimeActivated
RuntimeRollback
```

前端不能自行实现安装编排。

---

# 6. Runtime Provider

为了兼顾可复现和高级用户，Runtime 来源抽象为：

```text
RuntimeProvider
  ManagedImageProvider   # 正式默认
  OfflineImageProvider   # 本地 .hdi / offline bundle
  SystemProvider         # advanced/developer explicit opt-in
```

与参考项目不同，HarnessDock **不默认优先使用 PATH 中的 Node/dsh**。

原因：

- 可复现性；
- PATH 污染；
- 支持矩阵；
- 安全边界；
- 诊断一致性。

SystemProvider 必须显式开启并完整验证版本/能力，且不属于正式 Release 主链。

---

# 7. Host Kernel

```text
HostKernel
  dispatch(command, context)
  set_intent(intent)
  snapshot()
  subscribe()
  shutdown()
```

内部只持有：

- Actor handles；
- Event Bus；
- Desired State；
- Reconciler；
- Recovery Policy；
- Capability Broker；
- Runtime Store handle；
- Settings Store；
- immutable Build Manifest。

Kernel 不直接持有 Child、Window、Socket、download file handle 或 updater transaction。

---

# 8. Resource Ownership First

真实资源只有唯一 owner：

```text
RuntimeActor
  owns Process / Job / ProcessGroup / RuntimeLease

SurfaceActor
  owns WebviewWindow / navigation generation

GatewayActor
  owns Listener / Sessions / Pairing state

UpdateActor
  owns desktop update transaction

RuntimeStoreActor
  owns download/install/activate transaction
```

禁止：

- 全局共享 `Mutex<Option<Child>>`；
- 多模块持有相同 PID/Handle 的控制权；
- Tray/Menu/Shell 直接操作 Child；
- 多个 AtomicBool 拼装生命周期；
- UI 直接修改 active Runtime pointer。

---

# 9. Explicit State Machines

## 9.1 RuntimeActor

```text
Stopped
 -> ResolvingImage
 -> Preparing
 -> Starting
 -> Probing
 -> Ready
 -> Degraded
 -> Stopping
 -> Stopped

任何启动阶段 -> Cancelling -> Stopped
任何阶段 -> Failed
```

Restart 不是 bool，而是新的 generation intent。

## 9.2 RuntimeStoreActor

```text
Idle
 -> Resolving
 -> Downloading
 -> Verifying
 -> Assembling
 -> Activating
 -> Idle

Downloading/Verifying/Assembling -> Cancelling -> Idle
任何阶段 -> Failed
```

## 9.3 SurfaceActor

```text
Absent
 -> Creating
 -> Loading(generation, navigationId)
 -> Visible
 -> Hidden
 -> Closing
 -> Absent

Loading -> Failed
```

## 9.4 GatewayActor

```text
Disabled
 -> Binding
 -> Ready
 -> Draining
 -> Disabled

任何阶段 -> Failed
```

# 10. Runtime Generation + Lease

每次启动：

```text
RuntimeGeneration {
  id,
  nonce,
  imageId,
  mode: Normal | Quarantine | Safe,
}
```

ready handshake 必须绑定：

- generation；
- nonce；
- PID；
- exact `127.0.0.1`；
- port；
- dsh version；
- active image identity。

RuntimeLease：

```text
RuntimeLease {
  generation,
  imageId,
  pid,
  origin,
  privateAppUrl,
  dshVersion,
}
```

规则：

- `privateAppUrl` 永不进入公共 snapshot；
- Surface/Gateway 必须绑定同一 generation；
- generation 改变后旧 lease 自动无效；
- stale callback 无权影响当前资源。

---

# 11. Desired State + Reconciler

```text
HostDesiredState {
  app: Running | Quitting,
  runtime: Stopped | Running(RuntimeIntent),
  harnessSurface: Hidden | Visible,
  gateway: Disabled | Enabled(GatewayConfig),
  update: Idle | Installing(UpdateCandidate),
}
```

资源图：

```text
AppSession
  |
  +-- RuntimeImage
  |      |
  |      +-- Runtime
  |              |
  |              +-- HarnessSurface
  |              +-- Gateway
  |
  +-- DesktopUpdate
  +-- Diagnostics
```

Reconciler 只决定“下一步需要哪个 Actor 做什么”，不直接操作资源。

---

# 12. Runtime Version Management

借鉴参考项目 Core version manager，但采用 immutable image slots：

```text
candidate
active
previous
```

规则：

1. 下载 candidate image；
2. candidate 完整验证；
3. 原子切换为 active；
4. previous 保留；
5. 新 active 启动成功达到健康阈值后标记 committed；
6. 启动连续失败时自动 rollback previous；
7. 不删除当前/previous 依赖 layer；
8. 旧 image 由 GC 策略清理。

网络不可用：

- active 完整 -> 正常启动；
- active 缺失 -> Bootstrap/Recovery Surface；
- 可导入本地签名 `.hdi` image。

---

# 13. Host Protocol v2

业务入口统一：

```text
host_dispatch(CommandEnvelope) -> ResponseEnvelope
host_subscribe() -> HostEvent stream
```

保留少量 native window primitive 作为独立快速通道：

- minimize；
- maximize/restore；
- close；
- start drag。

这样 Runtime 下载/重启不会阻塞窗口控制。

CommandEnvelope：

```text
protocolVersion
requestId
subject
command
payload
```

所有 command/event/error/capability 从单一 schema 生成 TS SDK 和文档。

# 14. Capability Broker

授权决策输入：

```text
subject
surface
origin
requestedCapability
runtimeGeneration
hostMode
```

Capability 示例：

```text
window.control
web.reload
runtime.restart
runtime.manage-images
runtime.safe-mode
gateway.manage
diagnostics.read
update.check
update.install
app.quit
cli.manage
```

规则：

- Harness Surface 只得到必要能力；
- Recovery Surface 得到 recovery subset；
- Gateway Surface 得到 gateway subset；
- remote/mobile 页面永远没有 desktop native capability；
- Shell 只消费 capability snapshot，不假定命令存在。

---

# 15. Surface Architecture

不再存在常驻隐藏 `main`。

Surface：

```text
HarnessSurface       primary
BootstrapSurface     only when runtime missing
RecoverySurface      on failure
GatewaySurface       user requested
DiagnosticsSurface   user requested
```

Bootstrap/Recovery 成功后关闭。

正常启动不加载第二套控制 UI。

---

# 16. Native Gateway

Gateway 默认迁移到 Rust Native Gateway。

不再通过 Node sidecar + local bearer admin API 作为主路径。

GatewayActor owns：

- listener；
- RuntimeLease；
- pairing tickets；
- session keys；
- revocation state；
- rate limiter。

要求：

- public HTTPS；
- pairing 单次使用；
- Secure/HttpOnly/SameSite session；
- RuntimeLease 失效立即停止代理；
- revoke 为 actor command；
- secret 只存在 native secure store/memory；
- UI 只能获取脱敏 public snapshot。

---

# 17. CLI Integration

借鉴参考项目“安装后即可使用 dsh 命令”的体验，但由 Host 管理 active image。

```text
dsh shim
 -> locate HarnessDock Runtime Store
 -> resolve active image
 -> run active dsh with managed Node
```

规则：

- GUI/CLI 共用 active Runtime image；
- 不修改用户 shell rc 正文；
- PATH/shim 修改必须可逆；
- uninstall 能清理；
- CLI 不自动使用未经验证的 system Node；
- CLI 失败信息指向 Host Runtime repair，而不是静默安装另一套环境。

# 18. Plugin / Profile 策略

## 18.1 Host Integration Plugin

Host 必需的 dsh integration 不再作为用户目录里的 mutable built-in plugin。

它进入：

```text
Integration Layer
```

损坏时重新验证/下载 layer，不做启动时到处 repair 文件。

## 18.2 Community Plugin

社区插件仍归 dsh / DSH_HOME 管理。

Host 只负责：

- health observation；
- quarantine policy；
- recovery；
- 可选打开插件管理入口。

不把 Marketplace 变成 Host Kernel。

## 18.3 Preset Catalog

可以提供签名推荐 Catalog，但：

- 默认不安装第三方插件；
- 用户明确选择后才安装；
- Catalog 不增加 Host Installer 体积；
- Marketplace 继续由独立插件生态承载。

## 18.4 Profile

Host 可以支持：

```text
LaunchProfile(profileId)
```

但不复制完整 profile 编辑器。

# 20. Recovery Policy

失败分类：

```text
RuntimeMissing
RuntimeImageCorrupt
RuntimeLaunchFailed
PluginSuspected
HarnessLoadFailed
GatewayFailed
HostUpdateFailed
```

推荐策略：

```text
RuntimeMissing
 -> bootstrap managed image

RuntimeImageCorrupt
 -> disable active image
 -> previous image if available
 -> otherwise redownload/import

RuntimeLaunchFailed
 -> retry once
 -> quarantine suspected user plugins
 -> safe mode
 -> previous image when candidate caused regression
 -> RecoverySurface

HarnessLoadFailed
 -> recreate Surface
 -> same lease retry
 -> Runtime health probe
 -> RecoverySurface

GatewayFailed
 -> stop Gateway only
 -> never stop healthy Runtime/Harness
```

Recovery Policy 不直接操作资源，只改变 Desired State / issue actor commands。

# 21. Diagnostics

统一 typed event journal：

```text
HostEvent {
  seq,
  timestamp,
  correlationId,
  scope,
  kind,
  publicDetail,
}
```

禁止：

- token URL；
- Authorization；
- session secret；
- password；
- 未裁剪 raw stderr；
- 大文件无限增长。

Support Bundle 只导出脱敏：

- Host snapshot；
- active/previous image manifest；
- Runtime public state；
- bounded event journal；
- package/runtime version；
- platform info；
- redacted logs。

# 22. Settings v2

新 namespace，不迁移旧 Host 配置。

建议：

```text
settings.v2.json

gateway.v2.json

```

原则：

- secrets 不写普通 JSON；
- schema version；
- atomic write；
- corrupt file fallback；
- unknown field 可安全忽略；
- Runtime Store pointer 独立于 UI settings。

```text

maxHostVersion
```

## 23.3 Candidate Graph

```text
source SHA
  -> CI
  -> Host artifacts
  -> Runtime layers/images
  -> protocol fixtures
  -> package size report
  -> startup/download performance report
  -> SHA256SUMS
  -> signatures
  -> candidate manifest
```

Release 只能消费同一 Candidate Graph 中已验证对象。

```text

Runtime Image Update
```

它们通过 compatibility range 协调，而不是互相强绑定。

# 25. Verification Architecture

## 25.1 Model Test

纯状态模型生成随机 Intent：

```text
EnsureRuntime
RestartRuntime
StopRuntime
EnsureHarnessVisible
EnableGateway
DisableGateway
InstallRuntimeImage
InstallHostUpdate
Quit
```

永久不变量：

- at most one Runtime process owner；
- active image pointer 永远指向完整验证 image；
- stale lease 不产生 privileged action；
- Gateway Ready 必有有效 RuntimeLease；
- Harness Visible 必有有效 RuntimeLease；
- Quit 最终零 owned process/socket/window；
- failed download 不改变 active image。

## 25.2 Fault Injection

至少覆盖：

- manifest signature invalid；
- digest mismatch；
- interrupted Range download；
- mirror returns wrong bytes；
- disk full；
- extraction path traversal；
- Runtime crash before ready；
- wrong generation/nonce/PID；
- stale WebView callback；
- Gateway bind conflict；
- Runtime restart while Gateway active；
- update during Runtime download；
- quit during verification；
- candidate image boot failure -> rollback。

# 27. 最终不可回退规则

完成五轮后，代码不得重新出现：

- Electron desktop runtime；
- Host Bridge v1；
- hidden main control page；
- Runtime/Gateway 多 AtomicBool 生命周期；
- UI 编排 stop/start/restart；
- Shell/Tray/Menu 直调 Runtime implementation；
- Node Gateway sidecar 主路径；
- 默认 Full Runtime 塞入所有 Host 安装器；
- workspace 全量 node_modules 进入 bundle；
- unsigned/unverified Runtime activation；
- mutable Host-required built-in plugin repair；
- duplicated command/capability lists；
- public token URL；
- 用旧测试要求把旧架构重新加回来。

# 28. v0.2.0 完成定义

v0.2.0 只有同时满足以下条件才算完成：

1. 默认桌面安装包是 Host-only，小体积预算通过；
2. 首次启动可可靠获取、恢复下载、验证、激活 managed Runtime；
3. 离线已有 active Runtime 时完全可启动；
4. Offline Full Bundle 可导入/安装；
5. Runtime 支持 active/previous/candidate 与自动 rollback；
6. Runtime/Surface/Gateway/Update 为显式 Actor 状态机；
7. RuntimeLease 成为 Surface/Gateway 唯一依赖凭据；
8. Resource Graph + Reconciler 取代 UI 手工编排；
9. Host Protocol v2 + Capability Broker 为唯一业务边界；
10. Native Gateway 替代 Node admin sidecar 主路径；
11. CLI shim 与 GUI 使用同一 active Runtime；
12. Integration Layer 只含生产闭包；
13. Property/Model/Fault tests 通过；
14. 包体积、首次下载量、启动、重启、退出 SLO 有 CI 门禁；
15. Host/Runtime Candidate Graph 可追溯到精确 source SHA；
16. Windows/macOS/Linux/Android/iOS 当前支持范围全部验证；
17. 没有历史兼容层和孤儿流程；
18. PR 当前 head 的正式 CI 全绿。

这才是 HarnessDock v0.2.0 的最终新架构。
