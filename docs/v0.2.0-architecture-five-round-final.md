# HarnessDock v0.2.0 五轮架构重构最终方案

> 状态：**v0.2.0 最新且唯一有效的架构设计基线**  
> 日期：2026-09-03  
> 分发原则：**桌面安装包必须内置 Node + dsh；首次启动不下载 Node 或 dsh；断网也必须能直接进入 Harness Web。**  
> 参考 `dsh-tauri-desk/deepseek-harness-desktop` 只吸收经过验证的工程经验，不复制其首启下载 Runtime、Service/Workflow、状态模型、IPC 或产品 UI。

---

# 0. 最终产品定义

HarnessDock v0.2.0 定义为：

**DeepSeek Harness 的跨平台 Native Host Kernel + Immutable Embedded Runtime。**

HarnessDock 不是新的 Harness UI，也不是 Runtime 下载器。桌面安装包本身就是一个完整、可离线启动的产品闭包：

```text
Signed HarnessDock Installer
  |
  +-- Tauri Native Host
  +-- Host Protocol v2
  +-- Harness Shell / Host Integration
  +-- Embedded Full Runtime Image
       +-- compact official Node runtime
       +-- pinned official dsh production closure
       +-- target-native optional packages only
  |
  `-- first launch: zero Runtime download
         -> RuntimeActor
         -> RuntimeLease
         -> HarnessSurface
         -> Harness Web
```

移动端仍然不内置 Node/dsh，使用认证 Gateway 连接桌面/server Runtime：

```text
Mobile Tauri
  -> HTTPS Gateway
  -> authenticated session
  -> Native GatewayActor
  -> RuntimeLease
  -> desktop/server Harness Runtime
```

任何 Shell、Tray、Gateway 管理、Diagnostics、Update UI 都不能成为健康 Harness Web 正常启动的前置依赖。

---

# 1. 为什么仍然参考 deepseek-harness-desktop

参考项目的小安装包主要来自“Host 与 Node/dsh 分开发行，首次启动下载 Runtime”。这个具体分发策略 **不适用于 HarnessDock 的最终要求**，因此不采用。

但它仍有五类值得吸收的工程经验：

1. **Tauri 2 + 系统 WebView**：避免 Electron 自带 Chromium 的体积和内存成本；
2. **production-only dependency closure**：内置插件只打实际生产依赖，不复制 workspace 开发依赖；
3. **target-specific native pruning**：只保留当前平台/架构的 native addon/prebuild；
4. **下载/安装/诊断职责分离**：这类边界思想可以用于我们的 build pipeline，而不是首次启动；
5. **插件/Profile/CLI/系统集成体验**：可以借鉴产品能力，但必须通过 HarnessDock Host Protocol、Capability 和 Plugin 边界实现。

HarnessDock 的改进点是：

```text
参考项目：Small Host + first-run Runtime download
HarnessDock：Compact Full Installer + zero-download first launch
```

所以我们的体积优化目标不是“把 Runtime 移出安装包”，而是“让安装包中的 Runtime 只包含真正运行所需的字节”。

# 2. Embedded Full Runtime Image

## 2.1 Runtime 必须是安装包资源

桌面 Candidate 必须先生成目标平台 Runtime，然后放入：

```text
apps/tauri/src-tauri/resources/dsh-runtime/
```

Tauri 通过 `bundle.resources` 把它编入安装包。

Native Runtime 启动必须从应用资源目录解析 `dsh-runtime`，不能把“没有 Runtime”解释成首启下载任务。

如果 packaged Runtime 缺失或完整性不正确：

- Candidate 构建直接失败；
- 已安装客户端启动时 fail-closed 到 Recovery Surface；
- **禁止临时从网络下载 Node/dsh 补洞**。

## 2.2 Runtime 内容

最终 Runtime Image：

```text
dsh-runtime/
  manifest.json
  LICENSE                     # Node license
  node.exe                    # Windows
  # or bin/node               # macOS/Linux
  node_modules/
    @deepseek-ai/dsh/
    ... exact production closure ...
```

Node 官方发行包原本包含大量开发工具。正式 Candidate 只保留执行 dsh 必需内容：

### 保留

- `node.exe` 或 `bin/node`；
- Node `LICENSE`；
- dsh production closure；
- 当前平台/架构需要的 native optional dependencies；
- Runtime manifest。

### 删除

Windows：

- npm/npx/corepack wrapper；
- `node_modules/npm`；
- `node_modules/corepack`；
- `install_tools.bat`；
- `nodevars.bat`；
- Node README / CHANGELOG。

macOS/Linux：

- `bin/npm` / `bin/npx` / `bin/corepack`；
- `lib/node_modules` 中 Node 自带 npm/corepack；
- `include/` headers；
- `share/` man/docs；
- Node README / CHANGELOG。

删除 Node package manager **不能删除 dsh 自己的 root `node_modules` production closure**。

## 2.3 dsh production closure

Candidate Runtime 必须继续从固定上游 commit 生成官方 packed packages，再只安装 dsh 启动闭包。

禁止：

- 把 upstream monorepo 整体塞入 Runtime；
- 把 upstream devDependencies 带入 Runtime；
- 把所有平台 optional native packages 全部带入每个平台 Runtime；
- 从 workspace 根目录复制完整 `node_modules`。

继续保留当前优化：

- wrong-platform `@img/sharp*` pruning；
- non-host `prebuilds/*` pruning；
- Linux glibc/musl pruning；
- source maps / pdb / TypeScript declarations pruning；
- package test/example/coverage/.yarn pruning；
- 非 license/notice/changelog Markdown pruning。

所有 pruning 之后必须重新执行 Runtime integrity + startup smoke。

# 3. Runtime Manifest 与发布绑定

Runtime manifest 至少记录：

```text
schemaVersion
clientVersion
runtimeLayoutVersion
nodeVersion
dshVersion
dshGitTag
dshGitCommit
platform
arch
runtimeSource
nodeSource
nodeDistributionPruned
nodeDistributionPrunedBytes
productionClosurePrunedBytes
buildCommit
```

v0.2.0 的正式 Runtime 与客户端是一体发布关系：

```text
HarnessDock v0.2.0 Candidate SHA
        |
        +-- Windows Full Runtime
        +-- Linux Full Runtime
        +-- macOS x64 Full Runtime
        +-- macOS arm64 Full Runtime
        |
        `-- signed Tauri application assets
```

因此 v0.2.0 **不做后台 dsh Core 热替换**。升级 dsh 的正式路径是构建新的、经过完整 Candidate 验证的 HarnessDock 版本/候选，并通过签名 Tauri updater 安装。

这比“桌面客户端版本不变、Runtime 在后台悄悄升级”更容易保证：

- 可复现；
- 可回滚；
- Host/dsh 协议一致；
- 安全边界明确；
- CI 可以证明 exact SHA 对应 exact Runtime。

Developer 模式可以显式允许 system Node / custom Runtime override，但它不属于正式产品主路径。

# 4. Native Host Kernel

最终核心结构：

```text
Tauri Adapter
  |
Host Protocol v2
  |
Capability Broker
  |
Host Kernel
  |
Desired State / Event Bus
  |
Reconciler + Recovery Policy
  |
+---------------+----------------+--------------+
|               |                |              |
RuntimeActor SurfaceActor   GatewayActor   UpdateActor
|               |
RuntimeLease    Harness Web
```

原则：

- Actor 是真实 native resource 的唯一 owner；
- 状态是 enum，不是多个 AtomicBool 的组合；
- UI 表达 intent，不表达 stop/start procedure；
- Surface/Gateway 通过 RuntimeLease 依赖 Runtime generation；
- Reconciler 负责跨资源收敛；
- Capability Broker 决定哪个 subject 可以做什么；
- Optional layer fail-open，security boundary fail-closed。

---

# 5. Host Protocol v2

所有 Menu、Tray、Shell、Diagnostics 和未来 SDK 都应消费同一 typed contract。

Round 1 已开始落地：

```text
HostCommand
CommandEnvelope
HostResponse
ResponseEnvelope
HostError
HostSnapshot
Capability
SubjectKind
ProtocolVersion = 2
```

目标入口：

```text
host_dispatch(CommandEnvelope) -> ResponseEnvelope
host_subscribe() -> HostEvent stream
```

Native window primitive（minimize/maximize/close/drag）可以继续走最短 native 路径，以保证 Runtime 长操作时窗口始终响应。

Host Protocol 不允许把 Runtime token URL、Gateway secret 或 authorization 内容暴露给公共 snapshot/error。

# 6. Resource Actor 与 RuntimeLease

## RuntimeActor

最终状态：

```text
Stopped
 -> Preparing
 -> Starting
 -> Probing
 -> Ready
 -> Degraded
 -> Stopping
 -> Stopped

启动阶段 -> Cancelling -> Stopped
任何阶段 -> Failed
```

Restart 是 intent，不是 `restarting: bool`。

Actor 唯一持有：

- Child；
- Windows Job Object / Unix process group；
- current generation；
- validated RuntimeLease。

## RuntimeLease

```text
RuntimeLease {
  generation,
  image_identity,
  pid,
  origin,
  private_app_url,
  dsh_version,
}
```

Runtime generation 改变后，旧 Surface/Gateway lease 自动失效。

# 7. Surface Model

不再保留常驻隐藏 control page 作为第二套产品 UI。

Surface 只有：

- HarnessSurface：唯一主业务 Surface；
- RecoverySurface：失败时动态创建；
- GatewaySurface：用户主动打开；
- DiagnosticsSurface：用户主动打开；
- Splash/Bootstrap Surface：只负责短暂原生启动反馈，不做 Runtime 下载器。

正常桌面主链：

```text
Process Start
 -> verify embedded Runtime
 -> start Runtime
 -> validate ready handshake
 -> create/show HarnessSurface
 -> optional Shell injection
```

Shell 注入失败：恢复 native decorations，Harness Web 继续工作。

---

# 8. Native Gateway

最终目标仍是 Rust Native Gateway，避免 Node sidecar 带来的额外进程、local admin API 与 secret surface。

GatewayActor owns：

- listener；
- pairing ticket；
- session；
- revocation set；
- RuntimeLease；
- rate limiter。

远程/mobile Surface 永远没有 desktop privileged Tauri capability。

---

# 9. Plugin / CLI / Profile 能力借鉴

从参考项目可以借鉴，但不能侵入 Host Kernel：

## Plugin

- 推荐插件 Catalog；
- 插件状态/错误诊断；
- upgrade/remove；
- quarantine/safe-mode；
- first-party integration auto-heal。

社区插件不打进 Full Runtime，除非它是 HarnessDock 必需的 Host Integration，并且进入明确 production closure。

## Profile

- 支持查看/切换 dsh Profile；
- 不复制第二套 Harness Settings；
- Profile 的真实数据仍由 dsh 管理。

## CLI

可以提供 `dsh` shim 指向安装包内置 Node+dsh，达到“安装客户端后终端也可直接使用”的体验。

CLI shim 不复制 Runtime，也不能修改用户 shell 配置之外的系统环境；卸载时可完整清理。

---

# 10. 体积目标

由于 Node+dsh 必须内置，不能使用参考项目 6 MB Windows 安装包作为目标。

v0.2.0 第一阶段合理预算：

| Artifact | 第一阶段预算 |
| --- | ---: |
| Windows NSIS | <= 150 MB |
| Windows MSI | <= 170 MB |
| macOS DMG | <= 180 MB |
| Linux DEB | <= 160 MB |
| Linux AppImage | <= 190 MB |
| Full Runtime uncompressed | 建立实测基线后逐轮收紧 |

这些是上限，不是目标值。每个 Candidate 都要记录：

```text
host binary bytes
frontend bytes
Node bytes
dsh production closure bytes
integration bytes
installer bytes
```

体积增加超过阈值必须能回答“哪个分层增加了多少”。

# 11. 五轮重构

## Round 1 — Host Protocol / Adapter / Embedded Runtime Contract

- 修复当前 `bridge/desktop/service` 不完整分层；
- `lib.rs` 收敛成 composition root；
- Menu/Tray 统一转换成 typed HostCommand；
- 建立 Host Protocol v2 types；
- 建立 `check:embedded-runtime` 永久门禁；
- 确认 Candidate 必须把 Node+dsh 放入 Tauri resources；
- 首次启动零 Runtime 下载。

## Round 2 — RuntimeActor + Compact Immutable Runtime Image

- 替换 Runtime 多 AtomicBool；
- Actor 唯一进程 ownership；
- generation/cancellation；
- Node distribution pruning；
- dsh production closure pruning；
- Runtime manifest/hash；
- Job Object/process group；
- Runtime size report/gate。

## Round 3 — RuntimeLease + Reconciler + Surface

- RuntimeLease；
- Desired State；
- Resource Graph；
- Reconciler；
- Recovery Policy；
- 删除 hidden main 常驻控制页；
- stale navigation/generation 防护。

## Round 4 — Capability / Native Gateway / Shell v2 / CLI

- Capability Broker；
- generated protocol/capability SDK；
- Native Rust Gateway；
- Shell v2；
- bundled-runtime `dsh` CLI shim；
- Plugin/Profile management entry；
- secret boundary。

## Round 5 — Verification / Performance / Release

- Model test；
- property test；
- deterministic fault injection；
- fake clock；
- process/window/socket leak gate；
- startup SLO；
- artifact size gate；
- exact Candidate SHA / Build Manifest / updater provenance；
- 删除所有迁移期 bool、旧 bridge、sidecar 和源码位置兼容测试。

本方案不是纯规划。当前分支已经开始 Round 1：

- 补齐 `bridge.rs`、`desktop.rs`、`service/workflow.rs`；
- Menu/Tray 已统一走 typed intent boundary；
- `lib.rs` 已恢复 composition-root 结构；
- Host Protocol v2 typed model 已开始加入；
- Runtime 打包新增 Node distribution pruning；
- `bundle-runtime` 在原有 dsh production closure pruning 之后继续做 Node 自带开发工具裁剪；
- 新 manifest 标记 `runtimeEmbedded=true`、`firstLaunchRuntimeDownloadRequired=false`；
- 新 embedded-runtime contract 将加入 CI。

后续实现只允许朝本文结构收敛，不再恢复 Host-only / first-run Runtime download 方案。

# 13. 最终不可破坏不变量

1. 桌面安装包包含可启动的 Node+dsh。
2. 第一次启动不下载 Node/dsh。
3. 断网时只要安装包完整，Harness Web 必须可启动。
4. Candidate 缺失/损坏 Runtime 必须构建失败。
5. Runtime 正式升级与签名客户端发布绑定。
6. Harness Web 是唯一主业务 Surface。
7. Optional Shell/Tray/Diagnostics/Gateway/Updater 失败不阻断 Harness Web。
8. Runtime/Gateway resource ownership 唯一。
9. stale generation 永不影响当前 Runtime/Surface。
10. remote/mobile 永不获得 desktop privileged capability。
11. Android 保持当前 unsigned-compatible candidate policy。
12. Release tag 和既有 signed asset 不允许静默覆盖。
13. 所有架构、体积、安全与发布不变量必须有机器门禁。
