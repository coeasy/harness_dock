# HarnessDock v0.2.0 五轮架构重构最终方案

> 状态：**v0.2.0 最新且唯一有效的架构设计基线**  
> 日期：2026-09-03  
> 原则：不兼容旧 Host Core、Host Bridge v1、隐藏控制页、Electron、历史 v0.2.x 过渡逻辑；参考项目只吸收设计原则，不复制目录、模块、状态模型或产品行为。

---

# 0. 最终结论

HarnessDock v0.2.0 重新定义为：

**DeepSeek Harness 的跨平台 Native Host Kernel。**

它不是新的 Harness UI，也不是一个围绕 WebView 堆叠菜单的桌面壳。它负责：

- 固定并启动可信 Runtime Image；
- 唯一持有 Runtime / Gateway / Surface / Update 等长生命周期资源；
- 将产品意图收敛为 Desired State；
- 用 Resource Actor 串行管理真实资源；
- 用 Runtime Lease 表达跨资源依赖；
- 用 Reconciler 让实际状态持续收敛到目标状态；
- 用 Policy Engine 处理失败、降级、恢复；
- 用 Capability Broker 控制 Shell / Surface / Mobile / Diagnostics 的权限；
- 用 Host Protocol v2 作为所有 Native UI、Shell、Tray、Menu 和 SDK 的唯一业务协议；
- 用可重放事件、故障注入和发布不变量保证架构可验证。

桌面主链路只有一条：

```text
Tauri Adapter
  -> Host Protocol v2
  -> Host Kernel
  -> Desired State
  -> Reconciler
  -> RuntimeActor
  -> RuntimeLease
  -> SurfaceActor
  -> Harness Web
  -> optional Shell Extension
```

移动主链路只有一条：

```text
Mobile Tauri
  -> Host Protocol v2
  -> Gateway Client
  -> HTTPS authenticated session
  -> desktop/server Native Gateway
  -> RuntimeLease
  -> Harness Runtime
```

任何设置、诊断、Gateway 管理、恢复、更新都不能成为 Harness Web 正常启动的前置依赖。

# 1. 五轮推演为什么比三轮更完整

上一版三轮方案已经完成：

1. 传统分层被否决；
2. Actor + 显式状态机保留；
3. Resource Graph + Runtime Lease + Reconciler 成为核心。

但继续审计后，仍发现五类长期风险没有被独立解决：

| 风险 | 三轮方案不足 | 五轮方案修正 |
| --- | --- | --- |
| 协议演进 | Host Protocol v2 只有方向，没有长期不变量 | 单独建立 Protocol/Schema/Codegen 轮次 |
| 权限漂移 | Shell capability、Tauri permission、命令表仍可能分叉 | Capability Registry + Broker + 生成式契约 |
| Actor 正确性 | Actor 能串行，但不能证明状态机不存在非法路径 | Property Test + Model Test + Fault Injection |
| 发布闭包 | Runtime/Host/Shell/Gateway 版本关系仍可能靠脚本拼接 | Build Manifest + Release Graph + Provenance |
| 性能与可恢复性 | 启动 trace 只能观察，无法形成稳定 SLO | Startup Budget + deterministic recovery + leak gate |

所以新计划不是把三轮拆成五轮，而是增加两个以前缺失的架构层：

- **Round 4：Protocol / Capability / Security Contract**
- **Round 5：Verification / Performance / Release Invariants**

# 2. 最终架构原则

## 2.1 Resource Ownership First

每个真实资源只能有一个 owner：

```text
RuntimeActor  owns Child / Job / ProcessGroup / RuntimeLease
SurfaceActor  owns WebviewWindow / Navigation generation
GatewayActor  owns Listener / Sessions / Pairing state
UpdateActor   owns Update transaction
```

禁止：

- 全局 `Mutex<Option<Child>>` 被多个模块共享修改；
- PID/Handle 在业务层复制；
- Tray/Menu/Shell 直接 stop/start Child；
- 一个资源同时拥有多个生命周期 flag。

## 2.2 State Is Data, Not Flags

不再存在：

```text
runtime_starting
runtime_restarting
runtime_stopping
gateway_starting
web_action
```

改为显式状态：

```text
RuntimeState
SurfaceState
GatewayState
UpdateState
```

状态只允许 Actor 自己迁移。

## 2.3 Intent Before Procedure

UI 不再表达“先 stop Gateway，再 stop Runtime，再 start Runtime，再刷新 Web”。

UI 只表达：

```text
HostIntent::RestartRuntime { mode }
HostIntent::EnsureHarnessVisible
HostIntent::EnableGateway(config)
HostIntent::Quit
```

Reconciler 决定执行顺序。

## 2.4 Dependency Through Lease

Surface 与 Gateway 不保存一份可长期复用的 Runtime URL，而持有：

```text
RuntimeLease {
  generation,
  runtime_id,
  pid,
  origin,
  private_app_url,
  dsh_version,
}
```

Runtime generation 变化时，所有旧 lease 自动失效。

## 2.5 Protocol Is the Product Boundary

业务入口统一为 Host Protocol v2。

Tauri、Shell、Tray、Menu、Diagnostics、Mobile SDK 不直接依赖内部 Rust 模块。

## 2.6 Security Is Capability-Based

调用权限由：

```text
Subject + Surface + Origin + Capability + RuntimeGeneration
```

共同决定，而不是“这个 WebView 有 Tauri IPC 所以可以调用全部命令”。

## 2.7 Fail-Open Only at Optional Layers

Harness 主链必须 fail-closed 于安全边界，fail-open 于可选增强：

- Runtime handshake 错误：fail-closed；
- Runtime origin 不匹配：fail-closed；
- Gateway credential 无效：fail-closed；
- Shell 注入失败：fail-open，恢复 native decorations；
- Tray 创建失败：fail-open；
- Diagnostics 失败：fail-open；
- 自动更新不可用：fail-open，不影响 Harness Web。

# 4. Host Protocol v2

## 4.1 单一业务入口

Tauri 仅保留极少 native window primitive 和一个业务 dispatch：

```text
host_dispatch(CommandEnvelope) -> ResponseEnvelope
host_subscribe() -> HostEvent stream
```

窗口最小化/最大化/关闭可保留 native primitive，以保证即使 Kernel 忙碌也始终响应。

## 4.2 Command Envelope

```text
CommandEnvelope {
  protocol_version,
  request_id,
  subject,
  command,
  payload,
}
```

Command 是 tagged enum，不使用任意字符串 action。

## 4.3 Host Error

```text
HostError {
  code,
  scope,
  message,
  retryable,
  recovery_action,
  correlation_id,
}
```

公共 error 永不包含：

- Runtime token URL；
- Authorization；
- Gateway session secret；
- 文件中的 credentials；
- 原始第三方 stderr 全量。

## 4.4 Protocol 生成

`host-protocol` 是唯一 schema source。

CI 生成：

- TypeScript SDK 类型；
- Shell capability 类型；
- 文档命令表；
- snapshot JSON schema；
- protocol compatibility fixture。

禁止手写多份命令清单。

---

# 5. Host Kernel

```text
HostKernel
  dispatch(command, context)
  set_intent(intent)
  snapshot()
  subscribe()
  shutdown()
```

Kernel 只持有：

- Actor handles；
- Reconciler；
- Event Bus；
- Policy Engine；
- Capability Broker；
- Settings Store；
- immutable Build Manifest。

Kernel 不持有 Child、Window、Socket 或 updater transaction。

---

# 6. Desired State + Resource Graph

推荐目标状态：

```text
HostDesiredState {
  app: Running | Quitting,
  runtime: Stopped | Running(RuntimeMode),
  harness_surface: Hidden | Visible,
  gateway: Disabled | Enabled(GatewayConfig),
  update: Idle | Install(UpdateCandidate),
}
```

依赖图：

```text
AppSession
  |
  +--> Runtime
  |      |
  |      +--> HarnessSurface
  |      +--> Gateway
  |
  +--> Update
  +--> Diagnostics
```

规则：

- Surface 需要有效 RuntimeLease；
- Gateway 需要有效 RuntimeLease；
- Runtime stop 会先使 lease invalid，再触发依赖资源收敛；
- Update install 需要 Gateway disabled、Runtime stopped、Surface closed；
- Quit 目标状态优先级最高。

Reconciler 不直接操作 Child，只向 Actor 发命令。

---

# 7. Runtime Actor v2

## 7.1 状态机

```text
Stopped
  -> Preparing
  -> Starting
  -> Probing
  -> Ready
  -> Degraded
  -> Stopping
  -> Stopped

Preparing/Starting/Probing -> Cancelling -> Stopped
任何阶段 -> Failed
```

Restart 不是状态，而是新的 desired generation。

## 7.2 Generation + Handshake

```text
RuntimeGeneration {
  id: u64,
  nonce: 256-bit random,
  mode: Normal | Quarantine | Safe,
}
```

`ready.v2.json` 至少包含：

```json
{
  "schemaVersion": 2,
  "generation": 42,
  "nonce": "...",
  "pid": 1234,
  "host": "127.0.0.1",
  "port": 43123,
  "dshVersion": "...",
  "url": "http://127.0.0.1:43123/?token=..."
}
```

必须同时校验 nonce、generation、PID、host、port、origin。

## 7.3 Process Ownership

Windows：

- 使用 Job Object；
- `KILL_ON_JOB_CLOSE`；
- Actor owns Job + Process；
- 正常退出不依赖全系统 PID 扫描。

Unix：

- 独立 process group；
- TERM -> grace -> KILL。

孤儿扫描只允许在 repair/diagnostics 模式使用。

## 7.4 Immutable Runtime Image

Runtime Image 必须有 manifest：

```text
runtime-manifest.json
  imageSchema
  nodeVersion
  dshVersion
  dshCommit
  platform
  arch
  files[]
  hashes[]
  buildCommit
```

正式产品默认只使用 bundled Runtime Image。

system Node 仅 developer override，不属于发布主链。

---

# 8. Surface Actor v2

不再存在常驻隐藏 `main`。

Surface 类型：

- HarnessSurface；
- RecoverySurface；
- GatewaySurface；
- DiagnosticsSurface。

Harness Surface：

```text
Absent
 -> Creating
 -> Loading(generation, navigation_id)
 -> Visible
 -> Hidden
 -> Closing
 -> Absent

Loading -> Failed
```

规则：

- WebView 必须绑定 RuntimeLease；
- Finished/Failed callback 必须同时匹配 generation + navigation_id；
- 旧 callback 自动丢弃；
- 只允许当前 lease exact origin；
- RuntimeLease 失效后禁止旧页面继续获得 Host capability；
- Shell 注入失败恢复 native decorations。

---

# 9. Native Gateway v2

默认实现迁移到 Rust Native Gateway，不再使用 Node sidecar 作为主路径。

GatewayActor owns：

- listener；
- pairing tickets；
- sessions；
- revocation set；
- RuntimeLease；
- rate limiter。

状态：

```text
Disabled
 -> Binding
 -> Ready
 -> Draining
 -> Disabled

任何阶段 -> Failed
```

安全要求：

- local admin API 不再暴露给 Web UI；
- pairing ticket 单次使用；
- session HttpOnly/Secure/SameSite；
- public origin 必须 HTTPS；
- loopback debug 是单独 developer mode；
- RuntimeLease 失效立即停止代理新请求；
- session/pairing secret 只存在 native memory/store；
- revoke 是 actor command，不经过本地 bearer admin token。

---

# 10. Capability Broker

Capability 不是静态布尔表，而是可验证授权决策。

输入：

```text
CapabilityRequest {
  subject,
  surface,
  origin,
  runtime_generation,
  capability,
}
```

输出：Allow / Deny + reason。

Capability 示例：

- `window.minimize`
- `window.toggle-maximize`
- `web.reload`
- `runtime.restart`
- `runtime.safe-mode`
- `gateway.manage`
- `diagnostics.open`
- `update.check`
- `update.install`
- `app.quit`

远程 Gateway Harness 页面默认不能获得 desktop privileged capabilities。

Shell 菜单直接由 capability snapshot 渲染，不再手工维护另一份 command list。

---

# 11. Recovery Policy Engine

恢复策略不写在 Runtime 启动函数的嵌套 `if/else` 中。

```text
RecoveryInput {
  failure_class,
  generation,
  recent_failures,
  suspected_plugins,
  user_intent,
}

RecoveryDecision {
  action,
  reason,
  user_message,
}
```

优先级：

1. normal；
2. confirmed quarantine；
3. diagnostic-selected quarantine；
4. safe profile；
5. RecoverySurface。

必须保证：

- 不直接重写用户真实 DSH 配置；
- 每个 generation 恢复次数有硬上限；
- 不允许无限 restart loop；
- recovery decision 可在 unit/property test 中独立验证。

---

# 12. Settings v2

新 schema 不兼容旧 Host store。

```text
HostSettingsV2 {
  schema_version: 2,
  window,
  close_behavior,
  gateway,
  update,
  recovery,
  diagnostics,
}
```

敏感项使用平台 credential store 或独立 secret store，不写入普通 JSON。

配置写入采用：

```text
temp -> fsync -> atomic rename
```

读取失败使用默认值 + diagnostics event，不阻塞 Runtime。

---

# 13. Update / Release v2

UpdateActor 使用事务模型：

```text
Idle
 -> Checking
 -> CandidateReady
 -> PreparingInstall
 -> Installing
 -> RestartRequested
```

发布关系由 Build Manifest 固化：

```text
Host Release
  -> Tauri Binary
  -> Runtime Image
  -> Shell package
  -> Protocol schema
  -> Gateway implementation
  -> updater metadata
```

所有产物必须绑定同一 `sourceCommit`。

禁止：

- tag force move；
- asset clobber；
- candidate 与 release source SHA 不一致；
- Runtime manifest 与 Host manifest 不一致；
- updater JSON 指向另一个 commit 的资产。

建议产出：

- SHA256SUMS；
- build-manifest.json；
- SBOM；
- provenance/attestation；
- updater signature；
- protocol schema digest。

Android 继续保持 unsigned-compatible candidate 策略，除非产品发布策略另行改变。

iOS v0.2.0 仍可保持 Simulator artifact，正式设备分发另立发布策略。

---

# 14. Diagnostics v2

Diagnostics 不读取全局可变对象拼页面，而消费 typed snapshot/event journal。

```text
HostSnapshot
  app
  runtime_public
  surface
  gateway_public
  update
  capabilities
  recent_events
```

必须提供：

- secret-free public snapshot；
- bounded event journal；
- startup trace；
- process ownership summary；
- actor mailbox health；
- state transition violations；
- support bundle export。

Support bundle 默认排除：

- token URL；
- Authorization；
- Gateway session cookie；
- private app URL；
- credential store；
- 用户消息内容。

# 15. 可验证架构

这是五轮方案相对上一版最重要的补强。

## 15.1 Model Test

建立纯模型：

```text
ModelRuntime
ModelSurface
ModelGateway
ModelUpdate
ModelReconciler
```

随机生成 intent 序列，对比 model state 与 actor snapshot。

## 15.2 Property Test

必须验证不变量：

- 任意时刻最多一个 owned Runtime；
- stopped Runtime 不存在有效 lease；
- Surface visible 必须有匹配 generation 的 lease；
- Gateway ready 必须有匹配 lease；
- Quit 最终收敛到所有资源 stopped；
- Update Installing 时 Runtime/Gateway 不运行；
- stale generation 事件永远不能改变新 generation 状态。

## 15.3 Fault Injection

至少覆盖：

- spawn 前取消；
- spawn 后 ready 前崩溃；
- ready 写一半；
- ready nonce 错；
- Runtime ready 后立即退出；
- WebView stale Finished；
- Shell inject 失败；
- Gateway bind 失败；
- Runtime restart 时 Gateway 正在 pair；
- update install 时 Runtime 正在 restart；
- process stop 超时；
- settings 写盘失败。

## 15.4 Deterministic Time

Actor/recovery/update 测试必须支持 fake clock，禁止大量真实 sleep 导致 flake。

# 16. 性能目标

建议将性能从观察指标升级成 release gate：

| 指标 | 目标 |
| --- | --- |
| Host process -> Runtime spawn | P95 < 500 ms（不含 dsh 自身冷启动） |
| Runtime ready -> WebView request | P95 < 150 ms |
| WebView ready -> visible | P95 < 300 ms（页面本身之外的 Host 开销） |
| window primitive response | P95 < 50 ms |
| graceful quit coordinator overhead | P95 < 2 s，不含系统强杀回退 |
| leaked managed child after exit | 0 |

性能门禁只统计 Host 自己控制的开销，不把网络和上游 Harness 渲染时间错误归因给 Host。

# 17. 五轮完成后的产品行为

用户启动 HarnessDock：

```text
Kernel boot
 -> desired runtime=Running
 -> RuntimeActor creates generation
 -> ready.v2 verified
 -> RuntimeLease published
 -> desired harness_surface=Visible
 -> SurfaceActor loads exact origin
 -> visible Harness Web
```

正常用户不会看到设置页。

Runtime 失败：

```text
Actor emits failure
 -> Policy decides recovery
 -> next generation
 -> success => Harness Web
 -> exhausted => dynamic RecoverySurface
```

用户开启 Gateway：

```text
Gateway intent Enabled
 -> Reconciler verifies RuntimeLease
 -> GatewayActor binds
 -> pairing/session native-managed
```

用户退出：

```text
App desired=Quitting
 -> revoke capabilities
 -> Gateway drain
 -> Surface close
 -> Runtime stop
 -> Update transaction settle/cancel
 -> Kernel shutdown
 -> process exit
```

# 18. 明确删除的旧机制

五轮完成后代码树中不应继续存在：

- Electron desktop host；
- Host Bridge v1；
- 隐藏常驻 `main` 控制页；
- Runtime/Gateway 多 AtomicBool 生命周期；
- `runtime_status` 等大量独立业务 Tauri command；
- Tray/Menu/Shell 到 Runtime module 的直接调用；
- Node Gateway sidecar 主路径；
- Gateway local bearer admin API；
- UI 手工编排 stop/start/reload 链；
- 全局 `Mutex<Option<Child>>` 资源 ownership；
- system Node 自动发现作为默认发布行为；
- 同一 capability 的多份手写命令列表；
- 旧 Host settings migration；
- 旧 v0.2.x 方案作为现行实现约束。

# 19. 最终架构完成定义

v0.2.0 只有同时满足以下条件才算架构完成：

1. `lib.rs` 仅为 composition root；
2. 所有长生命周期资源由 Actor 唯一拥有；
3. Runtime/Gateway 不再依赖生命周期 AtomicBool；
4. Surface/Gateway 都通过 RuntimeLease 依赖 Runtime；
5. UI/Shell/Tray/Menu 都只通过 Host Protocol v2；
6. Native window primitive 始终独立可响应；
7. Gateway 主路径为 native implementation；
8. Recovery 为独立 Policy Engine；
9. Capability 来自单一 Registry/Broker；
10. Protocol/SDK/docs 由 schema 生成并做 drift gate；
11. Model/property/fault tests 覆盖主要状态不变量；
12. Windows/macOS/Linux desktop 构建与 Runtime smoke 全绿；
13. Android/iOS 现有目标构建全绿；
14. upstream compatibility smoke 全绿；
15. candidate 产物与最终 release source SHA 完全一致；
16. 没有托管 child 泄漏；
17. 没有 token/credential 进入公共 diagnostics；
18. 文档索引只指向当前五轮基线。
