# HarnessDock v0.2.0 五轮架构重构最终方案

> 状态：**v0.2.0 最新且唯一有效的架构设计基线 / 五轮一次性收尾版**  
> 日期：2026-09-03  
> 执行原则：**Round 1–5 不再作为五次停顿点，而是五个并行关联的架构工作流；全部在同一实施分支连续完成，最后只做一次统一验收、合并与发布。**  
> 分发原则：**桌面安装包必须内置 Node + dsh；首次启动不下载 Node 或 dsh；断网也必须能直接进入 Harness Web。**

---

# 0. 最终产品定义

HarnessDock v0.2.0 定义为：

**DeepSeek Harness 的跨平台 Native Host Kernel + Immutable Embedded Runtime。**

HarnessDock 不是第二套 Harness UI，也不是 Runtime 下载器。桌面安装包本身必须形成完整、可离线启动、可验证、可回滚的产品闭包：

```text
Signed HarnessDock Installer
  |
  +-- Tauri Native Host
  +-- Host Protocol v2
  +-- Capability Broker
  +-- Reconciler / Recovery Policy
  +-- RuntimeActor / SurfaceActor / GatewayActor / UpdateActor
  +-- Harness Shell / Host Integration
  +-- Embedded Full Runtime Image
       +-- compact official Node runtime
       +-- pinned official dsh production closure
       +-- pinned pnpm tool for plugin management
       +-- target-native optional packages only
  |
  `-- first launch: zero Runtime download
         -> verify embedded Runtime
         -> RuntimeActor
         -> RuntimeLease
         -> HarnessSurface
         -> Harness Web
```

移动端不内置 Node/dsh，通过认证 Gateway 连接桌面/server Runtime：

```text
Mobile Tauri
  -> HTTPS Gateway
  -> authenticated session
  -> Native GatewayActor
  -> current RuntimeLease
  -> desktop/server Harness Runtime
```

任何 Shell、Tray、Gateway 管理、Diagnostics、Update、Plugin UI 都不得成为健康 Harness Web 正常启动的前置依赖。

---

# 1. 五轮一次性实施模型

v0.2.0 不再采用“Round 1 验收后停下，再进入 Round 2”的串行项目管理方式。

五个 Round 重新定义为五个**架构责任域**：

```text
Round 1  Protocol / Adapter / Embedded Runtime Contract
Round 2  RuntimeActor / Immutable Runtime / Process Ownership
Round 3  RuntimeLease / Reconciler / Surface / Recovery
Round 4  Capability / Native Gateway / Shell / CLI / Plugin
Round 5  Verification / Performance / Size / Release
```

执行方式：

```text
same implementation branch
  -> continuous code migration across Round 1-5
  -> delete superseded legacy paths immediately
  -> continuously repair compile/test/CI failures
  -> no intermediate “Round complete” declaration
  -> one final five-round convergence gate
  -> merge
  -> exact-main-SHA candidate
  -> release
```

因此：

- 可以因为 Round 3 的 Lease 需求反向修改 Round 2 RuntimeActor；
- 可以因为 Round 5 property test 发现状态漏洞而继续修 Round 2/3；
- 可以因为 Round 4 Capability 发现 Protocol 设计不足而继续修 Round 1；
- 不保留“为了阶段验收暂时兼容旧架构”的长期桥接层；
- **五轮只有一起完成，没有单独完成。**

# 2. Embedded Full Runtime Image

桌面 Candidate 必须先生成目标平台 Runtime，再放入：

```text
apps/tauri/src-tauri/resources/dsh-runtime/
```

正式 Runtime 必须由应用资源目录解析，禁止把 Runtime 缺失解释成首启下载任务。

如果 packaged Runtime 缺失或完整性错误：

- Candidate 构建直接失败；
- 已安装客户端 fail-closed 到 Recovery Surface；
- 禁止临时联网下载 Node/dsh 补洞。

最终 Runtime Image：

```text
dsh-runtime/
  manifest.json
  LICENSE
  node.exe | bin/node
  node_modules/
    @deepseek-ai/dsh/
    ... exact production closure ...
  tools/
    pnpm/
      ... pinned plugin-management tool ...
```

正式主路径只保留执行 dsh 和插件管理所需字节：

- Node binary + LICENSE；
- dsh exact production closure；
- 当前平台/架构 native optional dependencies；
- Runtime manifest；
- 独立 pinned pnpm tool。

删除 Node 官方发行包的 npm/npx/corepack、headers、man/docs、开发 helper 等无关内容，但**不能误删 dsh 自己的 production closure，也不能让 `dsh plugin` 依赖用户系统 pnpm**。

所有 pruning 后必须重新执行：

```text
manifest validation
 -> integrity check
 -> dsh startup smoke
 -> plugin-tool smoke
 -> Runtime size report
```

# 3. Runtime Manifest 与发布绑定

Runtime manifest 至少记录：

```text
schemaVersion
clientVersion
runtimeLayoutVersion
nodeVersion
dshVersion
dshGitTag
dshGitCommit
pnpmVersion
platform
arch
runtimeSource
nodeSource
buildCommit
imageIdentity
runtimeSha256
nodeDistributionPrunedBytes
productionClosurePrunedBytes
runtimeTotalBytes
```

正式发布必须形成单向可证明关系：

```text
HarnessDock Candidate SHA
  -> exact Runtime manifest
  -> exact Node/dsh/pnpm identity
  -> exact platform package
  -> updater manifest/signature
  -> SHA256SUMS
  -> release tag
```

v0.2.0 不做后台 dsh Core 热替换。升级 dsh 的正式路径是新的 HarnessDock Candidate / Release。

Developer 模式可以显式允许 custom Runtime/system Node override，但不得进入正式 Candidate 主路径，也不得影响生产门禁。

# 4. Native Host Kernel

最终核心结构：

```text
Tauri Adapter
  |
Host Protocol v2
  |
Capability Broker
  |
Host Kernel
  |
Desired State / Event Bus
  |
Reconciler + Recovery Policy
  |
+---------------+----------------+--------------+-------------+
|               |                |              |             |
RuntimeActor SurfaceActor   GatewayActor   UpdateActor   Diagnostics
|               |
RuntimeLease    Harness Web
```

核心规则：

1. Actor 是真实 native resource 的唯一 owner；
2. 生命周期状态必须是 enum，不允许多个 AtomicBool 组合成并行真相；
3. UI 只表达 intent，不直接编排 stop/start/restart procedure；
4. Surface/Gateway 只能通过当前 RuntimeLease 访问 Runtime；
5. Reconciler 负责 desired state 与 actual state 收敛；
6. Capability Broker 决定 subject 是否有权执行 command；
7. Optional layer fail-open，security boundary fail-closed；
8. Harness Web 正常可用优先于 Shell/Tray/Settings/Gateway UI 完整性。

---

# 5. Host Protocol v2

所有 Menu、Tray、Shell、Diagnostics、Gateway Surface 和未来 SDK 消费同一 typed contract：

```text
HOST_PROTOCOL_VERSION = 2
HostCommand
CommandEnvelope
HostResponse
ResponseEnvelope
HostError
HostSnapshot
HostEvent
Capability
SubjectKind
RuntimePhase
RuntimeGeneration
```

目标入口：

```text
host_dispatch(CommandEnvelope) -> ResponseEnvelope
host_snapshot() -> HostSnapshot
host_subscribe() -> HostEvent stream
```

Native window primitive（minimize/maximize/close/drag）可继续走最短 native 路径，以保证 Runtime 长操作时窗口仍然响应。

Host Protocol 不得把 Runtime token URL、Gateway secret、pairing ticket、session secret 或 authorization material 暴露到公共 snapshot/error/event。

最终必须建立单一 schema/codegen source，生成：

- Rust protocol types；
- TypeScript Shell SDK types；
- capability registry；
- command table；
- fixtures；
- compatibility tests。

删除长期手写重复 command/capability 列表。

# 6. RuntimeActor / RuntimeGeneration / RuntimeLease

## 6.1 RuntimeActor

最终状态机：

```text
Stopped
 -> Preparing
 -> Starting
 -> Probing
 -> Ready
 -> Degraded
 -> Stopping
 -> Stopped

Preparing/Starting/Probing
 -> Cancelling
 -> Stopped

任何阶段
 -> Failed
```

Restart 是新 generation intent，不是 `restarting: bool`。

最终必须删除生命周期真相：

```text
runtime_starting
runtime_restarting
runtime_stopping
```

RuntimeActor 唯一持有：

- child process；
- Windows Job Object / Unix process group；
- current generation；
- cancellation；
- validated RuntimeLease；
- current image identity。

## 6.2 RuntimeGeneration

每次启动生成：

```text
RuntimeGeneration {
  id,
  nonce,
  image_identity,
  mode,
}
```

所有异步 ready/probe/navigation/gateway 结果都必须携带 generation。旧 generation 结果必须被明确拒绝。

## 6.3 RuntimeLease

```text
RuntimeLease {
  generation,
  image_identity,
  pid,
  origin,
  private_app_url,
  dsh_version,
}
```

Runtime restart 后旧 lease 自动失效。Surface/Gateway 不保存“长期裸 URL”作为资源真相。

---

# 7. Process Ownership

Windows：

- RuntimeActor owns Process + Job Object；
- `KILL_ON_JOB_CLOSE`；
- restart/quit 必须能收掉整个子进程树。

macOS/Linux：

- 独立 process group；
- TERM -> grace -> KILL；
- quit/restart 不能残留 orphan Runtime。

PID 扫描只允许 diagnostics/repair，不允许作为常规 ownership 实现。

---

# 8. Desired State / Reconciler / Recovery

Desired State：

```text
HostDesiredState {
  app,
  runtime,
  harnessSurface,
  gateway,
  update,
  revision,
}
```

UI/Menu/Tray/Shell 只提交 intent；Reconciler 决定 procedure。

Recovery 顺序固定：

```text
Normal embedded runtime
 -> plugin quarantine
 -> safe profile
 -> RecoverySurface
```

Recovery 不允许下载另一份 Node/dsh。

Reconciler 必须满足：

- 幂等；
- stale generation 安全；
- cancellation 安全；
- quit 优先级最高；
- update/restart 不产生自锁；
- actor ownership 不跨模块复制。

---

# 9. Surface Model

桌面正常启动不再创建常驻隐藏 control renderer。

Surface 只有：

- HarnessSurface：唯一主业务 Surface；
- RecoverySurface：失败时动态创建；
- GatewaySurface：用户主动打开；
- DiagnosticsSurface：用户主动打开；
- Splash/Bootstrap Surface：只负责短暂启动反馈。

正常主链：

```text
Process Start
 -> verify embedded Runtime
 -> RuntimeActor start
 -> validate RuntimeLease
 -> create/show HarnessSurface
 -> optional Shell injection
```

Harness load callback 必须校验：

```text
runtime generation
+ navigation id
+ actual WebView URL/origin
```

stale callback 直接丢弃。

Shell injection 失败：

```text
restore native decorations
Harness Web continues
```

Shell 绝不能成为 Harness Web 可用性的单点故障。

---

# 10. Capability Broker / Security Boundary

授权输入：

```text
subject
surface
origin
runtime_generation
capability
```

输出：

```text
Allow
Deny(reason)
```

关键规则：

- `harness-web` 是不可信 Web subject，不因为 URL 看起来像 Harness 就获得 native privilege；
- NativeMenu/Tray/Diagnostics 是不同 subject；
- capability 判断必须结合真实 WebView label/origin/current RuntimeLease；
- 请求体中的 subject 不能覆盖真实调用来源；
- 远程/mobile Surface 永远不能继承 desktop privileged Tauri capability；
- Harness Shell 的 Tauri permission 收敛为 `host_execute/host_snapshot + 必要窗口 primitive`；
- restart/update/quit/plugin/gateway 等业务动作必须通过 Host Protocol + Capability Broker。

---

# 11. Native Gateway

默认 Node Gateway sidecar 被 Rust Native GatewayActor 取代。

GatewayActor owns：

- listener；
- pairing ticket；
- one-time connect token；
- HttpOnly/Secure session；
- revocation set；
- RuntimeLease；
- rate limiter。

禁止：

- Node sidecar 作为正式默认 Gateway；
- localhost bearer admin API；
- 长期固定 Gateway secret；
- Runtime generation 改变后继续使用旧 session/lease。

CI、打包和文档必须同时删除旧 Node Gateway sidecar 假设。

---

# 12. UpdateActor

Update 是独立状态机，不借用 Runtime/Web AtomicBool：

```text
Idle
 -> Checking
 -> Downloading
 -> Installing
 -> Restarting
 -> Idle | Failed
```

要求：

- 串行化 update action；
- GitHub latest release 与签名 updater manifest 版本一致；
- signature/public key 必须有效；
- restart 前停止所有 managed resource；
- Supervisor 不因等待 UpdateActor 回到 Idle 而产生 restart deadlock；
- exact candidate SHA 与 updater artifact 可追溯。

---

# 13. Plugin / Profile / CLI

## Plugin

Host 只提供管理入口，不复制 Harness 产品 UI：

- plugin status/error；
- add/remove/update；
- quarantine；
- safe-mode；
- recommended catalog；
- first-party integration auto-heal。

社区插件不打进 Full Runtime；Host 必需 integration 才允许进入 production bundle。

插件管理必须使用安装包内独立 pinned pnpm tool，不依赖用户系统 Node/pnpm。

## Profile

- profile list/switch；
- 真数据仍由 dsh 管理；
- 不复制第二套 Harness Settings。

## CLI

可选注册 `dsh` shim 指向安装包内置 Node+dsh：

```text
<resource>/dsh-runtime/node
<resource>/dsh-runtime/node_modules/@deepseek-ai/dsh/lib/bin.js
```

shim 不复制 Runtime、不下载 Runtime，卸载时可清理。

# 15. 当前收尾阻断项

五轮主体架构已经跨 Round 1–4 开始落地，但以下项目在全部修完以前一律视为 **未完成**：

## 15.1 Rust 当前真实编译错误

当前 GitHub `cargo check` 已确认至少存在：

1. `OriginInfo` 缺少 `Clone`；
2. `tray.rs` 仍访问已删除的 `harness_loading`；
3. `supervisor.rs` 存在 Mutex 临时借用生命周期错误；
4. 伴随 `gateway_host.rs` unused `Manager`、`process.rs` unnecessary `mut` 等 warning。

这些必须直接修复，不能通过恢复旧 AtomicBool 解决。

## 15.2 旧 CI contract

当前旧 gate 仍存在以下错误假设：

- 要求 system Node fallback；
- 搜索旧 AtomicBool；
- 验证旧临时目录/Runtime 标记；
- `tauri-ci` 仍构建 Node Gateway sidecar。

必须改成验证：

```text
sealed embedded Runtime
RuntimeActor
RuntimeGeneration
RuntimeLease
cancellation
Native GatewayActor
zero-download first launch
```

## 15.3 Capability 收口

旧 Harness Shell permission 仍可能直接暴露 restart/update/quit 等命令。最终必须缩成：

```text
host_execute
host_snapshot
minimum window primitives
```

业务动作全部经过 Capability Broker。

## 15.4 Round 5 证明不足

尚需补齐：

- stale-generation property tests；
- repeated restart/coalescing tests；
- stop-during-start/cancel tests；
- Gateway lease invalidation tests；

- update/restart race tests；
- packaged Runtime missing/corrupt tests；

# 17. 最终定义

v0.2.0 的完成标准不是“Round 1、2、3、4、5 分别做过一次”，而是：

```text
Protocol
+ Runtime ownership
+ Lease/Reconciler
+ Surface/Recovery
+ Capability/Gateway
+ Shell/Plugin/CLI
+ Verification/Release
```

共同收敛成**一套没有并行真相、没有孤儿逻辑、没有旧架构回退、没有隐藏控制 UI 依赖、可以离线启动并由 CI 证明的 Tauri Native Host**。

在统一最终验收门槛全部通过之前，文档、PR 和 Release 都不得宣称“五轮完成”。
