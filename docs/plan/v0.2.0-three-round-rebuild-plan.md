# HarnessDock v0.2.0 三轮重构执行计划

> 本文是 `docs/v0.2.0-architecture-rebuild-final.md` 的执行拆解。  
> 原则：**不做旧架构兼容迁移，不保留过渡层，不以“少改代码”为目标，以最终结构正确为目标。**

---

# 1. 执行原则

本轮重构采用三轮闭环，而不是一次大提交：

```text
Round 1  架构清场 + Host Kernel 骨架
   ↓ 审计
Round 2  生命周期/安全/恢复/Gateway 重建
   ↓ 审计
Round 3  产品闭环/发布/性能/清理/最终验证
```

每一轮都必须执行：

1. 删除上一轮已经判定不合理的设计。
2. 完成该轮全部代码与测试，不留“下一轮再修”的已知断链。
3. 做一次静态依赖审计。
4. 做一次状态机/并发审计。
5. 做一次用户主链路审计。
6. 修完本轮发现的全部真实问题后，才进入下一轮。

最终不是“3 次检查同一套代码”，而是 **3 次架构收敛**。

---

# 2. Round 1：架构清场与 Kernel 骨架

## 2.1 目标

把现有代码从“模块互相调用”重构成可继续演进的最终骨架：

```text
Tauri Adapter
  -> Host Protocol
  -> Host Kernel
  -> Resource Actors
```

这一轮不追求一次实现所有 Gateway/Recovery 细节，重点是彻底建立正确边界。

## 2.2 必删旧结构

删除或停止使用：

- 旧 Host Bridge apiVersion=1。
- 旧多业务 Tauri command 入口。
- 隐藏 `main` 常驻控制页启动职责。
- `runtime_starting/runtime_restarting/runtime_stopping` 组合状态。
- `gateway_starting` 这类跨 start/stop 共用 bool。
- Shell/Tray/Menu 直调 runtime/gateway/window workflow。
- `lifecycle.rs` 通过读取多个 bool 再推导真实状态的模型。
- 任何 Electron runtime/update/release 兼容残留。

历史文档、历史测试可以保留在 Git 历史，但不能继续约束新代码。

## 2.3 新 Cargo 结构

建立：

```text
crates/host-protocol
crates/host-core
crates/gateway-core
```

Round 1 先完成：

### host-protocol

- `HostCommand`
- `HostResponse`
- `HostError`
- `HostEvent`
- `HostSnapshot`
- `CapabilitySet`
- `ApiVersion = 2`

### host-core

- `HostKernel`
- `DesiredState`
- `RuntimeActor` 骨架
- `SurfaceActor` 骨架
- `UpdateActor` 骨架
- Event Bus
- Snapshot revision

### Tauri adapter

- `host_dispatch`
- app setup
- native run event
- menu/tray adapter
- window adapter

## 2.4 IPC 收敛

删除几十个业务 command 注册。

只保留：

```text
host_dispatch
```

平台必要的非业务 Tauri 内部 hook 可独立存在，但 Shell/Control UI 不直接消费。

所有动作转为：

```text
UI/Shell/Menu/Tray
 -> HostCommand
 -> HostKernel.dispatch
```

Menu/Tray 不允许直接 import `runtime::*`、`gateway::*`。

## 2.5 Runtime Actor 第一版

状态：

```text
Stopped
Preparing
Starting
Probing
Ready
Stopping
Failed
```

Round 1 必须实现：

- mailbox 串行化。
- generation id。
- actor 唯一持有 child。
- start/stop/restart command。
- cancellation 基础能力。
- Windows process owner abstraction。
- Unix process-group abstraction。

Restart 不允许存在独立 `restarting` bool。

## 2.6 Surface Actor 第一版

只实现：

- Harness Surface 动态创建。
- loading/visible/failed 状态。
- navigation id。
- runtime generation binding。
- shell injection timeout fallback。

不再启动隐藏控制页。

## 2.7 Round 1 架构测试

新增强制契约：

- `lib.rs` 不允许包含 Runtime/Gateway 业务分支。
- adapter 不允许直接 import runtime process implementation。
- actor 之外不允许持有 Child。
- Host Protocol 只能有 v2。
- 不允许出现 `runtime_restarting`。
- 不允许出现 `gateway_starting`。
- 不允许出现旧 Electron 主机目录/工作流。

## 2.8 Round 1 审计问题预期

完成骨架后重点寻找：

- HostKernel 是否开始变成 God Object。
- actor 是否互相直接调用。
- Window command 是否被 Runtime 长操作阻塞。
- restart 是否可以中途 quit。
- stale callback 是否仍有复活旧窗口可能。

发现即修，不把这些问题拖到 Round 2。

## 2.9 Round 1 完成标准

- 新 Kernel 可启动 Runtime 并打开 Harness Web。
- native window control 可工作。
- Shell 不存在也能使用原生 decorations。
- quit 可以取消 in-flight Runtime start。
- Rust/TS tests 全绿。
- 代码中不存在新旧两套生命周期并行运行。

# 3. Round 2：资源依赖、安全、Recovery、Gateway 重建

## 3.1 目标

Round 1 有 Actor，但跨 Actor 编排仍可能变成手工顺序。Round 2 引入最终核心：

```text
Resource Lease
Desired State
Reconciler
Policy Engine
Capability Broker
```

## 3.2 Runtime Lease

Runtime Ready 后只发布 `RuntimeLease`：

```text
RuntimeLease
  generation
  pid
  origin
  private_app_url
  dsh_version
```

规则：

- `private_app_url` 不出 host-core。
- public snapshot 只有 display origin。
- Surface/Gateway 不保存裸 upstream URL 作为有效性依据。
- generation 变化即 lease invalid。

## 3.3 Desired State

定义最少四种 intent：

```text
PrimaryReady
PrimarySafe
GatewayEnabled(config)
Stopped
```

Reconciler 只做：

```text
Current Snapshot + Desired State
 -> missing resources
 -> invalid leases
 -> actor intents
```

Reconciler 不持有资源句柄。

## 3.4 依赖图

```text
Runtime
  |- HarnessSurface
  `- Gateway

UpdateInstall
  -> Quiesce Gateway
  -> Close Surface
  -> Stop Runtime
```

运行时依赖关系必须在代码中有显式类型或 declarative table，禁止散落 if 顺序。

## 3.5 Runtime Handshake v2

增加：

- generation
- random nonce
- pid
- exact host/port
- dsh version

任何一项不匹配都视为该 launch attempt 失败。

删除仅靠 PID + ready 文件存在就接受的弱绑定。

## 3.6 Capability Broker

Harness Web 不能获得开放 Tauri 能力。

每个 Harness document 获得独立 `BridgeSession`：

```text
sessionId
windowLabel
runtimeGeneration
runtimeOrigin
capabilities
```

dispatch 验证：

- session id
- source window
- generation
- origin
- capability

Runtime restart/reload/navigation/window destroy 后旧 session 全部失效。

## 3.7 Shell v2

Shell 独立包保留，但完全改成 host-sdk v2。

新增 handshake：

```text
host.describe
host.subscribe
host.dispatch
```

失败策略：

```text
Shell success -> frameless shell
Shell timeout/fail -> native decorations
```

Shell 永远不是 PrimaryReady 的依赖。

## 3.8 Recovery Policy Engine

从 Runtime actor 中移出“该尝试哪种恢复”的决策。

输入：

```text
FailureContext
  stage
  generation
  exit_code
  diagnostic_summary
  plugin_inventory
  previous_quarantine
```

输出：

```text
RetryNormal
LaunchWithQuarantine
LaunchSafeOverlay
ShowRecovery
AbortBecauseShuttingDown
```

限制：

- 最大有限恢复次数。
- 禁止递归 restart。
- 禁止修改用户真实 DSH 配置。
- quarantine 必须 version-scoped + TTL。

## 3.9 Gateway Native 重建

删除：

- Node Gateway sidecar。
- gateway ready.json。
- local admin token。
- local admin API。
- sidecar start/stop publish race。

实现 `gateway-core` Rust service：

- native HTTP/WebSocket proxy。
- RuntimeLease input。
- pairing code。
- rate limit。
- session hash store。
- revoke/revoke-all。
- graceful drain。

Gateway actor 不允许自己查 Runtime URL；只能接收 Lease。

## 3.10 Dynamic Control Surfaces

拆成：

```text
RecoverySurface
GatewaySurface
DiagnosticsSurface
```

按需创建，用完关闭。

禁止重新引入一个“什么都管理”的 dashboard 页面。

## 3.11 公共错误模型

统一：

```text
HostError
  code
  message
  retryable
  action
  operation_id
```

public adapter 在返回前统一 redaction。

UI 不再接收任意 raw `String(error)`。

## 3.12 Round 2 安全测试

必须覆盖：

- 假 ready nonce。
- 旧 generation ready。
- stale BridgeSession。
- 非 Harness window 使用 shell command。
- origin 变化后的旧 session。
- Runtime restart 时 Gateway 自动 drain。
- Runtime restart 时旧 Surface 不可重新 show。
- public snapshot 不出现 `?token=`。
- support log 不出现 bearer/authorization/pairing code。

## 3.13 Round 2 完成标准

- Runtime/Gateway/Surface 通过 Lease 连接。
- 不存在裸 URL equality 作为生命周期正确性判断。
- 不存在 Gateway sidecar。
- 不存在隐藏控制页。
- 不存在 raw public error。
- Shell/Tray/Menu 全部只使用 Host Protocol。
- failure injection 全绿。

# 4. Round 3：产品闭环、发布、性能、最终清理

## 4.1 目标

前两轮解决“架构正确”；第三轮解决“可以长期维护和发布”。

## 4.2 Control UI 重写

`apps/tauri/control-ui` 使用轻量 TypeScript 模块，不引入大型 SPA 框架。

页面：

```text
recovery
  retry
  safe start
  clear quarantine
  diagnostics
  support bundle
  quit

gateway
  status
  public origin
  pairing
  devices
  revoke

diagnostics
  build/runtime version
  state snapshot
  event timeline
  export support bundle
```

没有常驻设置首页。

## 4.3 Shell 独立发布闭环

Shell 包必须能独立：

- build
- pack
- install
- read manifest
- negotiate API v2
- hide unsupported capability

增加 standalone host fixture，验证 Shell 不依赖 HarnessDock 内部源码路径。

## 4.4 Build Manifest

Candidate 生成不可变 manifest：

```text
productVersion
gitSha
hostApiVersion
runtime node/dsh versions
runtime hashes
shell hash
gateway protocol version
platform/arch
```

Release 只从 Candidate 下载并组装，不允许二次构建。

## 4.5 Workflow 清理

最终只保留正式 workflow。

删除：

- 一次性 apply workflow。
- 临时 migration workflow。
- Electron workflow。
- 重复 candidate workflow。
- 已废弃 v0.2.x 临时验证 workflow。

建议正式集合：

```text
ci.yml
host-core-ci.yml
tauri-ci.yml
upstream-contract.yml
candidate.yml
release.yml
```

## 4.6 Upstream Contract

不做“兼容历史 dsh”。

只验证当前 pinned dsh：

- CLI flags
- ready handshake plugin hook
- profile patch contract
- Harness Web boot
- shell injection position
- required Node engine

固定 dsh commit 变化时，contract 必须重新跑。

## 4.7 Update 重建

更新状态：

```text
Idle
Checking
Available
Downloading
ReadyToInstall
Quiescing
Installing
Failed
```

规则：

- check 在 PrimaryVisible 后异步。
- update 失败不影响 Harness Web。
- install 才触发 DesiredState=Stopped。
- quiesce 使用 Reconciler，不允许 updater 自己直接 kill Runtime。

## 4.8 性能治理

结构化采集：

```text
process_started
kernel_ready
runtime_spawned
runtime_ready
surface_first_paint
shell_ready/fallback
primary_visible
```

CI 保存 perf artifact，但 v0.2.0 初期只对 Host overhead 做硬门禁，不把外部 dsh 波动误判为 Host 回归。

## 4.9 并发/property test

Round 3 必须增加长序列随机测试。

建议 invariant：

```text
owned_runtime_count <= 1
gateway.lease == current_runtime_generation
surface.lease == current_runtime_generation
shutting_down => reject business command
shell_failure => runtime unchanged
stale_callback => no visible transition
cancelled_start => no child leak
```

至少执行 10k 条随机 transition sequence。

## 4.10 平台验证

Desktop：

- Windows x64
- macOS arm64
- macOS x64（如继续支持）
- Linux x64

Mobile：

- Android remote client smoke
- iOS simulator remote client smoke

Android 当前决策保持：

- 不新增 release signing verification gate。
- 不要求 `ANDROID_KEY_*`。
- 继续检查非 debug、非空、体积/Native library 基础质量。

## 4.11 用户主链路 10 场景

1. 正常冷启动直接 Harness Web。
2. Runtime 启动慢。
3. Runtime 启动失败。
4. Shell 插件加载失败。
5. 第三方 dsh 插件导致启动失败。
6. 用户点 Runtime restart。
7. Gateway 正在使用时 Runtime restart。
8. Runtime Starting 时用户 Quit。
9. Updater 检查失败。
10. Tray 不可用桌面关闭窗口。

每个场景都必须有唯一且明确的用户结果，不能停在 invisible process / blank window / orphan child。

# 5. 三轮之间的“禁止回退”规则

进入下一轮后，以下设计不允许重新出现：

## Round 1 后禁止

- 业务逻辑回到 lib.rs。
- 多个业务 Tauri command 重新扩张。
- actor 外持有 child。
- lifecycle bool 组合。

## Round 2 后禁止

- Surface/Gateway 直接保存裸 Runtime URL 作为 ownership。
- Gateway sidecar。
- hidden main dashboard。
- Shell v1 compatibility。
- raw public error。

## Round 3 后禁止

- 临时 workflow 留在 main。
- release 二次 build。
- release asset 覆盖同名不同内容。
- current head 未验证就使用旧 head 的绿色结果。

# 6. 推荐提交序列

建议分成清晰的可 review commit：

```text
1. chore: archive legacy v0.2.x architecture contracts
2. feat: introduce host-protocol v2
3. refactor: add host kernel and runtime actor
4. refactor: move primary surface to surface actor
5. refactor: replace lifecycle flags with actor state
6. feat: add runtime lease and reconciler
7. feat: add capability broker and bridge sessions
8. feat: add recovery policy engine
9. refactor: replace gateway sidecar with gateway-core
10. refactor: replace hidden control page with dynamic surfaces
11. feat: migrate shell to host sdk v2
12. feat: add build manifest and deterministic candidate
13. test: add property/failure-injection suites
14. ci: collapse workflows to final release graph
15. docs: align project docs with final v0.2.0 architecture
```

不要求严格一个提交对应一个 PR；但禁止用一个超大提交掩盖不同责任边界。

# 7. 每轮完成后的审计模板

## A. Ownership

- 谁拥有 Runtime child？
- 谁拥有 Gateway listener？
- 谁拥有 WebView？
- 是否存在第二个可修改相同资源的路径？

## B. Transition

- 每个资源是否有显式 state enum？
- 是否有非法 state combination？
- cancel/quit 是否可打断长操作？

## C. Dependency

- Gateway/Surface 是否通过 Lease？
- Runtime generation 改变后依赖是否自动失效？

## D. UI

- 正常启动是否只有 Harness Web 主链路？
- 辅助 Surface 是否按需？
- Shell 失败是否有 native fallback？

## E. Security

- 是否存在 wildcard capability + 无 session 验证？
- 是否有 token/secret 进入 public state？
- remote mobile document 是否完全没有 local Host capability？

## F. Release

- 当前 commit 是否有 exact candidate？
- Release 是否只复用 Candidate？
- 所有 manifest/hash 是否一致？

# 8. 最终完成定义

v0.2.0 重构完成不是“代码能编译”，而必须同时满足：

```text
Architecture
  no legacy host path
  actor ownership complete
  lease graph complete
  protocol v2 only
  dynamic surfaces only

Correctness
  no orphan process
  no stale surface resurrection
  no gateway/runtime split brain
  cancellation works
  quit idempotent

Security
  exact managed origin
  generation-bound session
  secret-free public state
  hashed gateway sessions

UX
  direct Harness Web startup
  shell fail-open
  recovery actionable
  gateway optional
  diagnostics optional

Release
  immutable candidate
  current-head CI only
  deterministic manifest/hash
  desktop updater signed
```

并执行 **3 轮完整验证，每一轮发现的问题必须在该轮清零后再继续**。

本文与 `docs/v0.2.0-architecture-rebuild-final.md` 一起构成 v0.2.0 新重构的完整实施基线。
