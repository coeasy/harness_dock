# HarnessDock v0.2.0 核心链路收口与全面优化方案

## 1. 文档目的

本方案用于把 HarnessDock v0.2.0 从“功能已经基本可用的 Tauri Host”进一步收口为“主链路稳定、边界一致、插件可拔、故障可恢复、发布可验证”的正式基础版本。

本阶段不继续扩张产品边界，不把 HarnessDock 做成第二套 Harness UI，也不重新引入 Electron。核心原则保持不变：

- Harness Web 是主体业务界面。
- Tauri 是唯一桌面 Host。
- 桌面启动默认直接进入 Harness Web。
- Runtime、Shell、Gateway、更新、诊断都是 Host 能力，不改变上游 DeepSeek Harness。
- Shell / Tray / Menu / Gateway / Updater 任一异常都不能阻断 Harness Web 主链路。
- Android 保持当前 unsigned-compatible candidate 发布策略：构建 APK/AAB、检查产物与包体，不要求 keystore / APK/AAB 签名验证。
- v0.2.0 版本线不继续上调，所有活跃版本契约保持 `0.2.0`。

## 2. 当前产品定位

```text
HarnessDock
├─ Tauri Host
│  ├─ Native Startup Coordinator
│  ├─ Window / Tray / Native Menu
│  ├─ Runtime Lifecycle Manager
│  ├─ Gateway Lifecycle Manager
│  ├─ Signed Desktop Updater
│  └─ Recovery / Diagnostics
├─ Bundled Full dsh Runtime (Desktop)
│  ├─ pinned Node
│  ├─ pinned DeepSeek Harness Runtime
│  ├─ embedded-client plugin
│  ├─ runtime compatibility plugin
│  └─ harness-shell plugin
├─ Harness WebView
│  └─ official Harness Web UI
└─ Mobile Remote Client
   └─ HTTPS Gateway -> Desktop/Server Runtime
```

桌面平台：Windows x64、Linux x64、macOS x64/arm64。

移动平台：Android Remote-only、iOS Simulator Remote-only。

## 3. v0.2.0 核心成功标准

### 3.1 启动成功标准

正常桌面启动必须严格形成：

```text
Process Start
  -> splash
  -> bundled Runtime spawn
  -> validated ready.json
  -> managed Harness WebView
  -> first successful Harness page load
  -> Shell bridge injection (optional)
  -> Harness Web visible
```

任何可选功能初始化失败不得中断该链路。

### 3.2 故障恢复标准

```text
normal Runtime
  -> existing quarantine retry
  -> diagnostic plugin isolation
  -> temporary safe-profile
  -> recovery UI
```

恢复逻辑必须：

- 不改写用户真实 DSH 配置。
- 不自动删除用户插件。
- 不让失败 Runtime/Gateway 遗留后台进程。
- 不让 Shell 注入失败产生不可关闭的无边框窗口。
- 给用户明确的下一步动作，而不是只有内部异常文本。

### 3.3 权限边界标准

受管桌面 Runtime 固定启动为：

```text
http://127.0.0.1:<ephemeral-port>
```

因此以下四层必须使用同一个 origin contract：

1. Runtime `ready.json` 校验。
2. Harness WebView 初始 URL 校验。
3. Harness WebView navigation guard。
4. Tauri `harness-shell` remote capability。

不再接受：

- localhost alias
- IPv6 `::1`
- `127.0.0.2` 等其它 loopback 地址
- HTTPS loopback alias
- 带用户名/密码的 URL
- 不同端口的同机服务

### 3.4 发布标准

- tag 不允许移动。
- 同名 Release asset 不允许静默覆盖。
- desktop updater 继续使用签名 Tauri updater。
- Android 不增加签名门禁，只验证 candidate 非空、非 debug 命名、包体和最大 native `.so` 预算。
- iOS 明确为 Simulator artifact，不冒充 App Store / physical-device 发行包。

## 4. 第一阶段：统一 Managed Runtime Origin Contract（P0）

### 4.1 问题

当前 Runtime spawn 已固定 `--host 127.0.0.1 --port 0`，Tauri capability 也已收紧为 `http://127.0.0.1:*`，但 Rust URL 校验仍存在允许 localhost / HTTPS 的历史逻辑。

这种“实际启动范围 < Native 校验范围 < Capability 范围”的漂移会产生假就绪：Native 认为页面合法，但 Shell bridge 实际无法授权。

### 4.2 方案

新增单一语义：`ManagedRuntimeOrigin`。

逻辑要求：

```text
scheme == http
host == 127.0.0.1
port in 1..=65535
username empty
password none
```

所有 Runtime/WebView 校验统一走同一函数或等价共享规则。

### 4.3 验收

- `https://127.0.0.1:*` 拒绝。
- `http://localhost:*` 拒绝。
- `http://[::1]:*` 拒绝。
- `http://127.0.0.2:*` 拒绝。
- `http://127.0.0.1:<ready.port>` 接受。
- navigation 必须与当前 Runtime origin 完全一致。

## 5. 第二阶段：Shell Fail-open 真正闭环（P0）

### 5.1 问题

Harness WebView 使用 `decorations(false)`。如果 Shell initialization/eval 被 WebView 拒绝，Harness Web 仍可能正常显示，但用户可能没有自定义窗口控制，也没有系统标题栏。

### 5.2 方案

Shell 注入成功：

```text
window decorations = false
custom shell controls active
```

Shell 注入失败：

```text
window decorations = true
native title bar becomes fallback
Harness Web remains visible
native menu remains available
```

后续 reload/navigation 如果 Shell 重新安装成功，可恢复 custom decorations 模式。

### 5.3 验收

- Shell 注入失败不隐藏 Harness Web。
- 注入失败后窗口仍可最小化/最大化/关闭。
- 不依赖托盘才能恢复窗口控制。
- fail-open 行为由 parity test 锁定。

## 6. 第三阶段：统一 Shell Command Registry（P0）

### 6.1 问题

目前以下位置分别维护命令：

- `packages/plugin-harness-shell/src/index.ts`
- `packages/plugin-harness-shell/src/web/shell.js`
- `apps/tauri/src-tauri/src/harness_shell.rs`
- Tauri permission manifest
- parity tests

已出现 `gateway.manage` 在 Host Bridge 存在但 plugin service capabilities 未声明的漂移。

### 6.2 方案

先建立一个逻辑上的稳定 registry：

```text
window.minimize
window.toggleMaximize
window.state
window.close
web.reload
web.restart
runtime.safe-mode
runtime.clear-quarantine
gateway.manage
diagnostics.open
app.update.check
app.update.install
app.quit
```

短期：同步所有静态声明并增加“一致性测试”。

中期：由 TypeScript registry 生成 shell capability manifest / Host Bridge contract，减少字符串多点维护。

### 6.3 验收

- plugin service capabilities 与 Host Bridge commandMap 完全一致。
- UI 不显示宿主未实现 command。
- 独立插件 build/pack 后仍保留完整 capability contract。

## 7. 第四阶段：Runtime / Gateway 生命周期状态机（P0）

### 7.1 目标

逐步降低多个 `AtomicBool` 组合状态产生非法组合的概率。

目标状态模型：

```text
Stopped
Starting { generation }
Ready { pid, origin }
Restarting { generation }
Stopping { generation }
Failed { code }
```

Gateway：

```text
Stopped
Starting
Ready
Stopping
Failed
```

### 7.2 第一阶段实现策略

v0.2.0 不做高风险大改写，先增加统一 snapshot 和 transition helper：

- 所有 UI/API 状态从 snapshot 输出。
- 所有 start/stop/restart admission 通过统一 helper 判断。
- 状态切换必须带 generation/token，避免晚到任务覆盖新状态。
- 保留现有 AtomicBool 作为底层互斥实现，逐步迁移。

### 7.3 需要锁定的竞态

- start + start
- start + stop
- start + app quit
- restart + update install
- Runtime restart + Gateway start
- Gateway stop + late sidecar publication
- Harness old page-load callback + new navigation

## 8. 第五阶段：Recovery UI / Gateway UI 明确模式化（P1）

当前 `main` 页面承担：

- startup recovery
- Runtime manual control
- Gateway host management
- mobile remote pairing

必须明确页面模式，而不是仅依赖多个 `hidden` class 组合。

定义：

```text
surfaceMode = recovery | gateway-host | mobile-remote
```

桌面正常健康状态从 Shell/Tray 打开：`gateway-host`。

桌面启动故障：`recovery`。

移动端：`mobile-remote`。

每种模式只展示必要区域。

## 9. 第六阶段：错误模型和用户操作建议（P1）

逐步把字符串错误升级为：

```ts
{
  code: 'RUNTIME_READY_TIMEOUT',
  userMessage: 'Harness Runtime 启动超时',
  technicalDetail: '...',
  suggestedAction: 'retry | safe-mode | diagnostics | quit'
}
```

优先覆盖：

- Runtime spawn failure
- ready timeout
- WebView navigation failure
- Shell injection failure
- Gateway start failure
- update check/install failure

UI 默认显示 `userMessage + suggestedAction`，technical detail 进入诊断窗口。

## 10. 第七阶段：Mobile Gateway 易用性（P1）

当前 Gateway 能力已经可用，但配置偏技术化。

下一步优化：

- Desktop Gateway 页面生成 `gateway URL + pairing code` 二维码。
- Mobile 扫码后自动预填 Gateway URL 和 pairing code。
- Gateway ready 后复制公开 URL / pairing code 一键操作。
- 运行中锁定 port/public URL，停止后才允许修改。
- 已配对设备明确展示 lastSeen / session expiration。

v0.2.0 可先完成数据结构和 UI 入口，不强制引入新的二维码依赖。

## 11. 第八阶段：文档/代码一致性门禁（P1）

当前 README 仍可能保留旧的 localhost/IPv6 ACL 描述。

增加长期 contract：

- README active architecture 不得宣称 IPv6/localhost 获得 Shell ACL。
- `harness-shell.json` 必须只有受管 127.0.0.1 HTTP patterns。
- Runtime source 必须包含 `--host 127.0.0.1`。
- Android candidate workflow 不得要求 `ANDROID_KEY_*`。
- Android package check 不得执行 `apksigner` / `jarsigner`。
- Electron active host/build/workflow 不得重新出现。

## 12. 第九阶段：独立 Harness Shell 插件验证（P1）

目标不是只验证源码字符串，而是验证发布形态。

建议新增：

```text
pnpm build
pnpm pack
extract tarball
verify manifest
verify lib/index.js
verify web/shell.js
load service in minimal host harness
verify fail-open registration
```

最终保证 `@dsh/plugin-harness-shell` 可以真正独立发布/安装。

## 13. 第十阶段：启动性能与可观测性（P2）

增加内部时间点：

```text
process_started
runtime_spawn_started
runtime_ready
webview_created
webview_finished
shell_injected
primary_visible
```

记录：

- Runtime cold start
- recovery start
- WebView load
- Shell inject
- total time-to-Harness

不默认上传遥测；优先用于本地诊断和 CI performance report。

## 14. 实施顺序

本轮直接执行：

1. 保存本方案。
2. 收紧 Runtime URL 为唯一 HTTP 127.0.0.1 contract。
3. 修复 Shell injection fail-open native decorations fallback。
4. 补齐 `gateway.manage` plugin capability 并增加 registry parity contract。
5. 增强 Runtime/Gateway transition contract tests，防止竞态回归。
6. 明确 main Web UI surface mode。
7. 修 README / implementation docs 的旧 ACL 描述。
8. 增加 Android unsigned-compatible policy contract。
9. 增加 Shell 独立包 contract test。
10. 运行当前 head 的 CI / tauri-ci / upstream-compat，根据真实失败继续修复。

## 15. 暂不做的事项

为了保持 v0.2.0 收口，不在本轮引入：

- Electron compatibility host。
- Android mandatory production signing。
- iOS App Store/TestFlight provisioning。
- 修改上游 DeepSeek Harness UI/Runtime。
- 自动重启插件安装流程。
- 大规模新产品功能。

## 16. 最终验收矩阵

### 主体链路

- [ ] desktop cold start 直接进入 Harness Web。
- [ ] Shell/Tray/Menu/Updater 任一失败不阻断主体。
- [ ] Runtime crash 可诊断/恢复。
- [ ] plugin safe-mode 不修改真实 DSH_HOME。
- [ ] quit 后 Runtime/Gateway/startup child 全部退出。

### 权限

- [ ] Shell bridge 只授权 `http://127.0.0.1:<managed-port>`。
- [ ] remote Gateway 页面没有本地 Tauri IPC。
- [ ] navigation 不能跳到另一个 loopback service。

### UI

- [ ] Shell 失败仍有系统窗口控制。
- [ ] Gateway 正常状态有明确入口。
- [ ] recovery 页面只在需要时出现。
- [ ] 长操作期间窗口控制保持可用。

### 发布

- [ ] v0.2.0 active versions 全部一致。
- [ ] 32x32 icon occupancy gate 通过。
- [ ] tag immutable。
- [ ] release asset immutable。
- [ ] Android unsigned-compatible candidate 可直接构建发布。
- [ ] current-head CI / tauri-ci / upstream-compat 全绿后才合并。
