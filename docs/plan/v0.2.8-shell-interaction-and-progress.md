# v0.2.8 外壳交互、执行态与启动恢复方案

## 目标

本轮以桌面端的正常用户路径为唯一验收主线：启动后直接进入 Harness Web；插件诊断只在用户主动点击时打开；刷新、Runtime 重启和插件隔离恢复都不再表现为白屏或无响应；退出时继续回收 Runtime、Gateway 及其子进程。

## 产品决策

### 主界面层级

Harness Web 是唯一主工作区，外壳标题栏只保留一个操作入口和窗口控制：

`操作⌄ ｜ 最小化 ｜ 最大化/还原 ｜ 隐藏到托盘`

“刷新 Web”“重启 Runtime 并刷新 Web”“清除插件隔离并重启”“插件诊断”和“自动更新”统一放在“操作”下拉菜单中。前三个恢复动作和自动更新直接在当前 Web 窗口执行；只有用户明确选择“插件诊断”时才打开诊断窗口。这样可以消除顶部独立诊断按钮与菜单项的重复，同时不会让标题栏被多个高风险按钮挤满。

插件诊断窗口的职责是 Runtime、插件隔离、更新配置、日志和退出诊断，不承担正常工作区，也不重复执行主界面的恢复动作。窗口采用单例、非模态、按需创建、居中显示；关闭时隐藏，下一次点击直接复用。它不在启动阶段预创建，也不参与 Harness Web 首屏。

### 启动路径

桌面端使用三个明确角色：

| 窗口 | 角色 | 启动时可见性 |
|---|---|---|
| `splash` | 本地启动/恢复进度 | 可见，居中、无装饰、不可关闭 |
| `main` | 隐藏 Bootstrap/失败恢复页 | 隐藏 |
| `harness` | 正常 Harness Web | Runtime 和页面加载完成后可见 |

设置/插件诊断窗口不出现在配置文件的启动窗口列表中，只有 `shell_settings_show` 被用户触发后才创建。`settings` 页面完成加载后才显示，避免白板 WebView。

启动状态至少包括：

1. 正在初始化客户端；
2. 正在准备本地 Runtime；
3. 正在启动 Harness Runtime；
4. 正在打开 Harness Web；
5. 启动失败，正在打开插件诊断/恢复页。

正常成功路径在 Harness 页面加载完成时隐藏 `splash`，并隐藏 `main`。失败路径隐藏 `splash` 后显示 `main` 恢复页，保留重试、诊断和退出入口。

### 刷新与重启执行态

所有主界面操作使用统一执行状态：

```text
idle → running → success
                 └→ failure
```

`running` 阶段必须同时满足：

- 顶部状态点旋转，中央过渡提示显示当前动作；
- 触发按钮和其他外壳命令暂时禁用，防止重复启动或并发导航；
- 交互菜单自动关闭，Escape 或点击外部可关闭菜单但不能中断原子操作；
- Runtime 重启先停止 Gateway，再停止/启动 Runtime，最后重新打开 Harness Web；
- 刷新只导航 WebView，不替换 Runtime/Gateway；
- 刷新和重启导航期间显示 `splash`，页面加载完成后由 Tauri 回调关闭，避免用户看到白屏。

`failure` 阶段必须恢复可操作界面并显示明确错误，不得静默吞掉 ACL、导航、Runtime 或 Gateway 错误。

### 插件隔离恢复

“清除插件隔离并重启”是一个原子宿主命令：先清除持久化隔离记录，再走与普通 Runtime 重启相同的 Gateway/Runtime/Web 顺序。主 Web 外壳、插件诊断、应用菜单和托盘共用该命令，前端不直接获得隔离文件读写权限。

### 自动更新

自动更新位于主界面的“操作”菜单、应用菜单和系统托盘，均调用同一个 `update_install` 宿主命令，避免多套更新逻辑产生状态分叉。插件诊断页只展示更新策略，不再提供第二套更新按钮。

更新流程固定为：比较 GitHub 最新稳定 Release → 若有新版本则读取签名清单 → 校验版本与签名 → 显示下载进度 → 安装 → 通过统一退出流程关闭 Runtime/Gateway 和子进程 → 重启客户端。下载或安装期间显示本地 splash 和主界面执行态，失败时恢复当前界面并显示错误。

安全前提是构建时注入 `HARNESSDOCK_UPDATER_PUBLIC_KEY`，发布流水线生成与之匹配的签名安装包和 `latest.json`。当前公开 v0.2.7 发布资产没有这套 Tauri updater 元数据，因此本轮代码在未配置公钥时会明确提示“自动更新尚未启用”，插件诊断仍提供对应发布页作为人工降级路径；不能把普通 GitHub Release API 或未签名安装包冒充自动更新。

## ACL 与安全边界

- `main` 只拥有本地 Bootstrap 所需命令和 `splash_status`；
- `harness` 只通过 loopback URL capability 获得外壳命令；URL pattern 使用 Tauri URLPattern 兼容的 `/*` 路径形式；
- `settings` 只拥有插件诊断数据读取、诊断刷新和退出命令，不拥有主界面 Web/Runtime/更新动作；
- 外部 Harness 页面永远不获得本地 Gateway、文件或进程权限；
- Rust 端再次校验 URL 仅为 HTTP(S) loopback，前端 capability 不是唯一安全边界；
- 所有命令加入 `build.rs`、权限 TOML、capability 和 `generate_handler!`，并由契约测试同时检查，避免“编译通过但运行时 ACL 拒绝”。

## 退出与竞态

退出继续统一经过 `request_exit`：设置退出闸门、阻止新启动、停止 Gateway、停止 Runtime 进程树、回收启动中尚未登记的进程，最后退出 Tauri。窗口关闭只隐藏到托盘；托盘/插件诊断中的“退出 HarnessDock”才执行真正退出。

必须覆盖：

- Runtime/Gateway 启动尚未完成时退出；
- 刷新/重启过程中退出；
- 主窗口、诊断窗口和托盘重复触发退出；
- Node 子进程和孙进程；
- Runtime 异常退出后的状态刷新。

## 发布前验收矩阵

| 场景 | 期望结果 | 自动检查 |
|---|---|---|
| 冷启动 | 先见启动动画，成功后直接见 Harness Web | 配置、启动契约、桌面 smoke |
| 启动失败 | 外壳不退出，显示恢复页和诊断入口 | Runtime failure smoke |
| 点击插件诊断 | 居中、紧凑、非白板、可复用；不重复出现恢复按钮 | settings page-load/ACL 契约 |
| 点击刷新 Web | 有旋转执行态，不重启 Runtime，不白屏 | Web action smoke |
| 点击 Runtime 重启 | 先关 Gateway，完成后回到新 Web | Rust 生命周期检查 |
| 点击插件隔离恢复 | 清理记录并完成一次完整重启 | command/permission 契约 |
| 菜单动作 | 刷新、重启、插件恢复、更新在当前 Web 窗口直接执行；诊断仅主动打开 | 操作菜单/执行态契约 |
| ACL | `shell_settings_show`、刷新、重启均可用 | capability URL + permission 双检 |
| 窗口关闭 | 隐藏到托盘，不残留错误控制页 | tray/lifecycle smoke |
| 真正退出 | Node、Gateway、Runtime 子进程全部结束 | process tree cleanup |
| 无障碍 | reduced-motion 下仍有文本状态，不依赖动画 | CSS 静态检查 |
| 自动更新 | 菜单可触发；签名和清单未配置时明确降级，不误装未知包 | updater command/permission 契约；签名发布 smoke |

## 发布门禁

本轮代码先进入独立 PR，必须通过 Node 契约测试、Tauri 三平台 Rust 检查、Android/iOS smoke 以及主分支同 SHA 校验后，才允许合并。合并后再单独执行版本号升级和候选构建；未完成签名配置前，自动更新命令只能给出明确降级提示，不能伪装成静默安装。
