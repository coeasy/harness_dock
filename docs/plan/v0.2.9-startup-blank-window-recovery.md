# HarnessDock v0.2.9 启动白板与异常退出修复方案

## 1. 问题定性

v0.2.8 的桌面启动关键路径由隐藏的 `main` WebView 执行 JavaScript：页面先通过 IPC 启动 Runtime，再创建隐藏的 `harness` WebView，最后依赖 `PageLoadEvent::Finished` 才显示 Harness Web。这个链路同时受隐藏页面加载、IPC 初始化、WebView 导航回调和窗口可见性时序影响。

当其中任一环节失败时，可能出现以下组合故障：

- 用户看到白板或未完成绘制的窗口；
- `main` 与 `harness` 都处于隐藏状态，用户没有恢复入口；
- 所有窗口短暂不可见时，Tauri 触发自动退出请求；
- Runtime 已启动但 Harness 页面未打开，退出时还可能留下子进程；
- `harness-shell` capability 只覆盖带路径的 URL，根路径 WebView 调用外壳命令时出现 `Command ... not allowed by ACL`。

这不是单个按钮故障，而是启动状态机没有把“宿主存活”和“Web 页面就绪”分开。

## 2. v0.2.9 目标

桌面端的正常路径固定为：

```text
Tauri 宿主启动
  → 本地 splash 显示进度
  → Rust 启动并登记 Runtime
  → 校验 loopback URL
  → 创建 Harness WebView（未完成加载前不显示）
  → 页面完成绘制后显示 Harness Web
```

设置/插件诊断不参与启动。`main` 只作为隐藏 Bootstrap 和失败恢复入口，用户正常启动时不会看到它。

## 3. 实现改造

### 3.1 原生启动协调器

新增 `src-tauri/src/startup.rs`，在 Tauri `setup` 阶段启动一次：

- 由 Rust 直接启动 Runtime，不再依赖隐藏 `main` 页的 `app.js`；
- Runtime 失败时保留 Tauri、托盘、splash 和恢复页；
- Runtime 成功但没有 Web 地址时进入可操作恢复页；
- Harness Web 导航失败不会调用退出，也不会把白板当作成功；
- `main` 的 JavaScript 只负责移动端入口和桌面失败后的重试。

### 3.2 WebView 可见性与看门狗

- Harness WebView 继续以 `visible=false` 创建；只有页面 `Finished` 后才 `show + focus`；
- 完成加载后统一隐藏 splash 和 recovery `main`，避免旧页面重新露出；
- 20 秒内没有完成首次绘制时显示恢复页，提示 Runtime 仍在宿主内并提供重试；
- 刷新不隐藏现有 Web 页面，避免刷新期间出现白板；
- 重启失败显示恢复页，不再展示失效的 Harness WebView；
- 托盘“打开 Harness”不会提前显示仍在加载的隐藏 WebView。

### 3.3 防止意外退出

窗口切换期间所有窗口可能暂时隐藏。`RunEvent::ExitRequested` 只有在统一退出协调器设置 `quitting=true` 后才允许继续，否则调用 `prevent_exit`。

显式退出仍执行既有清理顺序：

1. 设置退出闸门；
2. 停止接受 Runtime/Gateway 新操作；
3. 终止启动中尚未登记的 PID；
4. 终止 Runtime、Gateway 及其子进程树；
5. 最后一次幂等清理；
6. 允许 Tauri 退出。

### 3.4 ACL 根路径兼容

`harness-shell` capability 同时覆盖 loopback 根 URL 和带路径 URL：

- `http://127.0.0.1:*` 与 `http://127.0.0.1:*/*`；
- `http://localhost:*` 与 `http://localhost:*/*`；
- 对应 HTTPS 形式。

这样动态 Runtime 返回根路径、`/` 或其他子路径时，主 Web 的菜单、插件诊断和窗口控制都使用同一组权限，不再出现启动后才发现的 ACL 拒绝。

## 4. 发布前验收

### 自动门禁

- `node --check apps/tauri/web/app.js`；
- `node --check apps/tauri/web/settings.js`；
- `pnpm check:versions`；
- `pnpm check:release`；
- Tauri parity：原生 startup、ExitRequested 防误退、Harness 看门狗、设置按需、ACL 根路径；
- Tauri Linux/macOS/Windows `cargo check`；
- Tauri Rust `cargo test --lib`；
- Android/iOS 原生 smoke；
- Full Runtime、四平台 Runtime、桌面包、Android APK/AAB、iOS 包构建；
- candidate、main CI、Release 使用同一提交 SHA；
- Release 必须含 13 个非空资产和 `SHA256SUMS`。

### 人工验收矩阵

| 场景 | 期望结果 |
| --- | --- |
| 冷启动 | 首个工作窗口直接是 Harness Web，设置页不出现 |
| Runtime 慢启动 | 只显示 splash，不显示白板；超时转入恢复页 |
| Runtime 启动失败 | 宿主不退出，显示具体错误、重试、诊断和退出入口 |
| Harness 首次加载失败 | 不显示空白 WebView，恢复页可操作 |
| 点击插件诊断 | 居中、紧凑、有完整内容；不预创建、不白板 |
| 菜单/标题栏命令 | ACL 允许，执行时有动画和文字反馈 |
| 刷新 Web | 保持 Runtime 和当前内容，导航后标题栏恢复 |
| 重启 Runtime | 先关闭 Gateway，得到新 Runtime 后再打开 Web |
| 托盘打开 | 加载中的 WebView 不会被提前显示为白板 |
| 关闭窗口 | 隐藏到托盘，不退出 Runtime |
| 明确退出 | Tauri、Runtime、Gateway、Node 子孙进程全部结束 |
| 启动中退出 | 不遗留刚创建但尚未写入状态表的进程 |

### 客户端验证边界

本版本将 Tauri 作为唯一正式客户端、启动宿主和发布门禁路径。旧 Electron
兼容源码暂时保留用于迁移参考，但已移除 3 个仅服务旧宿主的诊断、国际化和
版本覆盖测试套件，避免 Electron 二进制缺失或旧宿主契约把 Tauri 发布误判为
失败。剩余测试均为共享逻辑或 Tauri 契约测试；正式候选仍必须执行桌面 Rust
检查、Android/iOS smoke、上游 Runtime smoke 和完整 Tauri candidate。

## 5. 发布结论

v0.2.9 必须在修复分支通过上述自动门禁和跨平台候选构建后才合并到 `main`。仅静态检查通过不能视为启动问题已解决；至少要确认 Tauri 三端 Rust 检查、桌面候选包、移动 smoke、candidate gate 和同 SHA Release 校验全部成功。
