# HarnessDock v0.2.0 Shell-first 落地说明

## 目标

v0.2.0 的默认用户路径只有一个：启动 HarnessDock 后，等待本地 Full Runtime 就绪，直接显示官方 Harness Web。设置、诊断、插件恢复和更新均属于按需的外壳操作，不再成为启动入口。

## 已落地的边界

```text
Tauri Host
  ├─ 原生启动协调器
  ├─ Full dsh Runtime（loopback）
  ├─ Harness WebView（Runtime ready 后才显示）
  └─ harness-shell dsh plugin
       ├─ 无边框顶部外壳
       ├─ 窗口控制
       ├─ Web 刷新 / Runtime 重启
       ├─ 隔离插件启动
       ├─ 清除插件隔离并重启
       ├─ 诊断窗口（按需）
       └─ GitHub 签名更新
```

- 外壳 UI 位于 `packages/plugin-harness-shell`，可作为独立 dsh 插件构建、发布和安装。
- Tauri 只负责注入 `SHELL_API_VERSION = 1` 的 Host Bridge；Harness Web 不依赖 Tauri 内部实现。
- Tauri 的 `main` 页面仅作为启动故障恢复页保留，不在正常启动时显示。
- 所有外壳动作都有互斥保护和可见状态；失败通过 toast/恢复页返回，不会关闭 Harness Web 主体。
- “隔离插件启动”使用临时 `DSH_HOME`，不改写用户真实插件配置；普通插件安装不会自动重启，重启由用户从菜单明确触发。
- Electron 客户端已移除；Tauri 是 v0.2.0 唯一桌面宿主，VS Code/Cursor 仅作为编辑器扩展入口。

## 版本对齐

以下版本必须与根 `package.json` 保持一致：

| 组件 | v0.2.0 |
| --- | --- |
| HarnessDock / workspace packages | `0.2.0` |
| Tauri config / Rust crate | `0.2.0` |
| `harness-shell` plugin / manifest | `0.2.0` |
| origin clientVersion / release manifest | `0.2.0` |
| pinned dsh Runtime | `0.1.2-alpha.1` |

门禁：

```bash
pnpm check:versions
pnpm check:release
pnpm test
pnpm build
```

## 外壳命令协议

Host 只暴露以下稳定命令；插件通过 `capabilities` 判断当前宿主是否实现：

| 命令 | Tauri |
| --- | --- |
| `window.minimize` / `window.toggleMaximize` / `window.close` | 支持 |
| `web.reload` | 支持 |
| `web.restart` | 支持 |
| `runtime.safe-mode` | 支持 |
| `runtime.clear-quarantine` | 支持 |
| `diagnostics.open` | 支持 |
| `app.update.check` / `app.update.install` | Tauri 签名 updater |
| `app.quit` | 支持 |

远程 Harness/Gateway 页面不获得本地 Tauri capability；只有校验过的 loopback Harness WebView 才获得 `harness-shell` capability。

## 启动与故障策略

1. Native startup coordinator 启动 Full Runtime。
2. Runtime ready 后创建/导航 Harness WebView。
3. WebView 完成首次绘制后才显示，启动超时显示恢复页。
4. 普通启动失败时，先按现有隔离记录重试，再按插件故障恢复；仍失败则进入临时安全配置。
5. 用户主动选择“隔离插件启动”时直接跳过用户插件配置，成功后仍回到 Harness Web。
6. Runtime、Gateway 和更新流程均由宿主托管，窗口关闭默认隐藏到托盘，不影响主体进程。

## 独立插件发布

插件包入口和资源：

```text
packages/plugin-harness-shell/
  manifest.json
  lib/index.js
  web/shell.js
```

构建：

```bash
pnpm --filter @dsh/plugin-harness-shell build
```

其它 dsh 宿主可安装该包并读取 `manifest.json`；若宿主未实现某命令，只需将对应 capability 置为 `false`，插件会隐藏该入口，Harness Web 仍可独立运行。

## 发布验收

- 启动成功：首个可见业务页面是 Harness Web，不是设置页或控制页。
- 外壳可用：最小化、最大化/还原、关闭/隐藏、菜单均可操作。
- 刷新只导航 Web，不重启 Runtime；重启动作先停旧 Runtime，再加载新 loopback URL。
- 隔离启动不修改用户 `DSH_HOME`，并在状态中标记 `safeMode=true`。
- GitHub 更新仅走签名更新链路；未配置签名时不得安装未验证可执行文件。
- 外壳动作失败时 HarnessDock 进程、Runtime 和恢复入口仍可用。
- Tauri capability 检查、工作区版本检查、单测和 Full Runtime 资源检查全部通过。
