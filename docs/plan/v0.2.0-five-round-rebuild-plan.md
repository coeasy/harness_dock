# HarnessDock v0.2.0 五轮重构执行计划

> 本文是 `docs/v0.2.0-architecture-five-round-final.md` 的唯一实施计划。  
> 原则：**不兼容旧架构，不建立长期过渡层，不以最小改动为目标；以最终结构正确、安装包足够轻、Runtime 可独立演进、状态可证明、发布可验证为目标。**

参考分析：

`docs/reference/deepseek-harness-desktop-size-and-feature-analysis.md`

---

# 0. 五轮总览

```text
Round 1
Protocol + Kernel + Adapter + Host-only Packaging
  ↓
Round 2
Layered Runtime Store + Download Engine + RuntimeActor
  ↓
Round 3
RuntimeLease + Resource Graph + Reconciler + Surface + Rollback
  ↓
Round 4
Capability Broker + Native Gateway + Shell v2 + CLI + Plugin Integration
  ↓
Round 5
Model/Fault Tests + Performance/Size SLO + Release Graph + Final Cleanup
```

五轮不是“先写完再检查五次”，而是五次连续架构收敛。

每轮都必须完成：

1. 代码建设；
2. 删除被本轮取代的旧机制；
3. 静态依赖审计；
4. 状态/并发审计；
5. 安全/密钥审计；
6. 用户主链审计；
7. 安装包/Runtime 分发审计；
8. 本轮自动化门禁；
9. 修完发现的真实问题；
10. 再进入下一轮。

禁止把已发现的核心断链写成“后续再修”。

# 1. Round 1：清空旧边界 + Host-only Package

## 1.1 目标

第一轮同时解决两个基础问题：

- 代码边界不清；
- 默认安装包承担了不应该承担的 Runtime 内容。

目标结构：

```text
Tauri Adapter
   |
Host Protocol v2
   |
Host Kernel
   |
Runtime Provider abstraction
```

并建立第一个 **Host-only Candidate**。

## 1.2 必须删除/停止使用

- Host Bridge apiVersion=1；
- 长期存在的大量独立业务 Tauri command；
- Tray/Menu/Shell 到 Runtime/Gateway implementation 的直接调用；
- hidden `main` 作为正常启动的一部分；
- Electron runtime/update/release/test；
- 旧 lifecycle bool 作为新架构状态真相；
- 默认把完整 Node + dsh Runtime 塞进所有 Host Installer；
- 任何复制 workspace 根 `node_modules` 的打包逻辑。

## 1.3 新建 crate / package

```text
apps/tauri/src-tauri/crates/
  host-protocol/
  host-core/
  host-testkit/

packages/
  host-sdk/
```

### host-protocol

至少定义：

```text
ProtocolVersion
CommandEnvelope
HostCommand
ResponseEnvelope
HostResponse
HostEvent
HostError
HostSnapshot
Capability
Subject
```

### host-core

第一轮只建立：

```text
HostKernel
EventBus
Intent
DesiredState
RuntimeProvider trait
SettingsStore v2
```

不要求第一轮立刻完成最终 Actor，但旧 UI/Tray/Menu 不允许继续新增直调路径。

## 1.4 lib.rs 收口

`lib.rs` 只允许：

```text
construct kernel
register adapters
register host_dispatch
forward RunEvent
shutdown
```

禁止出现：

- runtime start/restart procedure；
- gateway procedure；
- recovery branch；
- download implementation；
- plugin recovery implementation。

## 1.5 Host-only bundle

重写 Tauri resources：

保留：

- minimal web/control assets；
- generated protocol schema；
- minimal Shell assets；
- trust root；
- icons；
- updater metadata。

移除默认 bundle：

- Node；
- dsh Core；
- large Runtime closure；
- third-party preset plugins；
- source maps；
- docs/test fixtures；
- devDependencies。

## 1.6 内置 Integration production closure

参考项目 `pnpm deploy --prod` 的经验，建立独立检查：

```text
integration bundle package
 -> build
 -> pnpm deploy --prod
 -> inject workspace packages
 -> hoisted production closure
 -> materialize symlink
 -> verify entries
 -> size report
```

要求：

- 不得部署 root workspace；
- 不得包含 devDependencies；
- 不得存在 dangling symlink；
- 必须验证 package entry；
- 产物 <= 10 MB。

## 1.7 Host 包体积门禁

Round 1 先建立真实 baseline。

最终预算：

```text
Windows NSIS <= 15 MB
Windows MSI  <= 20 MB
macOS DMG    <= 20 MB
Linux DEB    <= 25 MB
Linux AppImage <= 100 MB
```

CI 输出 `package-size.json`。

字段：

```text
artifact
platform
arch
compressedBytes
budgetBytes
sourceCommit
```

## 1.8 Round 1 验收

- Host-only build 可以完成；
- Windows/macOS/Linux 安装器不包含 Node/dsh；
- Runtime missing 时打开 Bootstrap Surface，而不是崩溃；
- Host Protocol 可 roundtrip；
- lib.rs 不含业务流程；
- Shell/Tray/Menu 不再创建新的 direct implementation call；
- package-size 门禁存在；
- integration bundle 只含 production closure；
- 旧 Electron 路径为 0。

## 1.9 Round 1 审计问题必须修复

重点检查：

- 因移除 Runtime 导致启动白屏；
- Bootstrap Surface 依赖旧 hidden main；
- IPC 仍直接调用 runtime module；
- build scripts 仍偷偷复制 Runtime；
- bundled resources 仍有大文件；
- Tauri installer WebView/runtime 配置造成意外体积。

全部修完再进入 Round 2。

# 2. Round 2：Layered Runtime Store + Download Engine + RuntimeActor

## 2.1 目标

完成真正可用的 managed Runtime bootstrap：

```text
Runtime Registry
 -> Runtime Image Manifest
 -> Layer Download
 -> Verify
 -> Assemble
 -> Activate
 -> RuntimeActor
```

## 2.2 Runtime Store 目录

```text
runtime-store/
  manifests/
  layers/
    node/
    dsh/
    integration/
  images/
  pointers/
    active.json
    previous.json
    candidate.json
  downloads/
  staging/
  journal/
```

## 2.3 Runtime Registry

先使用 GitHub Release/static signed manifests。

建立：

```text
stable.json
beta.json
```

Channel Manifest 至少包含：

```text
schemaVersion
channel
imageId
manifestUrl
manifestDigest
signature
publishedAt
```

Host 内置 trust root。

## 2.4 Runtime Image Manifest

必须包含：

```text
imageId
platform
arch
hostProtocolRange
minHostVersion
maxHostVersion
nodeVersion
dshVersion
dshCommit
integrationVersion
layers[]
sourceCommit
signature
```

## 2.5 Download Engine

直接吸收参考项目已经证明有价值的能力：

- HTTP Range resume；
- retry；
- backoff；
- source fallback；
- progress；
- SHA-256；
- 下载取消；
- 超时；
- 原子落盘。

进一步增强：

- manifest signature；
- decompression bomb budget；
- archive path traversal guard；
- file count budget；
- disk-space preflight；
- bounded partial files；
- mirror 不进入 trust model。

## 2.6 RuntimeStoreActor 状态机

```text
Idle
 -> Resolving
 -> Downloading
 -> Verifying
 -> Assembling
 -> Activating
 -> Idle

Downloading/Verifying/Assembling
 -> Cancelling
 -> Idle

任何阶段 -> Failed
```

active pointer 只能由 Actor 改。

## 2.7 RuntimeActor 状态机

```text
Stopped
 -> ResolvingImage
 -> Preparing
 -> Starting
 -> Probing
 -> Ready
 -> Degraded
 -> Stopping
 -> Stopped

启动阶段 -> Cancelling -> Stopped
任何阶段 -> Failed
```

删除：

```text
runtime_starting
runtime_restarting
runtime_stopping
```

Restart = 新 generation intent。

## 2.8 Runtime handshake v2

启动生成：

```text
generation
nonce
imageId
```

Ready 必须匹配：

```text
schemaVersion
generation
nonce
pid
host=127.0.0.1
port
dshVersion
imageId
```

任一不匹配立即 fail-closed。

## 2.9 Process ownership

RuntimeActor 是唯一 Child owner。

Windows：

```text
Job Object
KILL_ON_JOB_CLOSE
```

Unix：

```text
process group
TERM -> grace -> KILL
```

正常 shutdown 不用全局 PID sweep。

## 2.10 首次启动体验

无 active image：

```text
Bootstrap Surface
  正在准备 Runtime
  Resolving
  Downloading Node
  Downloading Harness
  Verifying
  Activating
  Starting Harness
```

成功自动关闭 Bootstrap Surface 并打开 Harness。

失败：

- retry；
- view safe diagnostic；
- import offline image。

## 2.11 Round 2 验收

- clean machine 首次启动可完成；
- 下载中断后可续传；
- mirror 错误字节不能激活；
- manifest signature 错误不能激活；
- disk full 不破坏 active；
- cancelled download 不残留 candidate pointer；
- active image 永远完整；
- RuntimeActor 无非法 flag 组合；
- Runtime process zero leak。

# 3. Round 3：RuntimeLease + Reconciler + Surface + 多版本回滚

## 3.1 目标

第二轮仍只是“资源可以安全运行”。第三轮解决跨资源一致性：

```text
Runtime image
 -> Runtime
 -> Surface
 -> Gateway
```

通过 Lease + Resource Graph 自动收敛。

## 3.2 RuntimeLease

```text
RuntimeLease {
  generation,
  imageId,
  pid,
  origin,
  privateAppUrl,
  dshVersion,
}
```

只有 host-core 可以看到 `privateAppUrl`。

公共 UI 只看到：

```text
displayOrigin
runtimeVersion
imageId
state
```

## 3.3 Resource Graph

```text
RuntimeImage
   |
Runtime
   |
   +-- HarnessSurface
   +-- Gateway
```

Update/Quit 是更高优先级 intent。

## 3.4 Desired State

```text
app
runtime
harnessSurface
gateway
update
```

UI 不再写 procedure：

```text
Stop Gateway
Close Web
Stop Runtime
Start Runtime
Open Web
```

UI 只发送：

```text
RestartRuntime
EnsureHarnessVisible
```

## 3.5 Reconciler

Reconciler：

- 读取 Desired State；
- 读取 Actor snapshots；
- 检查 lease；
- 决定下一条 actor command；
- 不持有 Child/Window/Socket。

要求：

- convergence；
- idempotent；
- quit priority；
- stale generation ignored；
- no cyclic actor calls。

## 3.6 SurfaceActor

删除 hidden main。

Surface：

```text
HarnessSurface
BootstrapSurface
RecoverySurface
GatewaySurface
DiagnosticsSurface
```

Harness：

```text
Absent
 -> Creating
 -> Loading(generation, navigationId)
 -> Visible
 -> Hidden
 -> Closing
 -> Absent
```

Finished/Failed callback 必须同时匹配：

- runtime generation；
- navigation id。

## 3.7 Runtime version slots

实现：

```text
candidate
active
previous
```

激活流程：

```text
download candidate
 -> verify
 -> activate candidate
 -> start
 -> health threshold
 -> commit
```

失败：

```text
candidate failed repeatedly
 -> rollback previous
 -> restart
 -> emit RuntimeRollback
```

## 3.8 Layer GC

禁止简单“保留最近 N 个目录”。

按 manifest 引用：

```text
mark active
mark previous
mark pinned
mark downloading
sweep unreferenced old layers
```

GC 不得删除正在运行 Runtime 的 layer。

## 3.9 Offline import

定义 `.hdi`：

```text
manifest
layers
signature
```

导入仍需完整验证，不因“本地文件”降低安全等级。

## 3.10 Profile launch

可以新增：

```text
LaunchProfile(profileId)
```

但不新建完整 Profile 编辑器。

dsh profile 数据继续归 dsh 管理。

## 3.11 Recovery Policy

建立 typed failure：

```text
RuntimeMissing
RuntimeImageCorrupt
RuntimeLaunchFailed
PluginSuspected
HarnessLoadFailed
```

策略：

- image corrupt -> previous/redownload；
- candidate regression -> rollback；
- user plugin failure -> quarantine/safe；
- Surface failure -> recreate；
- optional failure 不停健康 Runtime。

## 3.12 Round 3 验收

- Runtime restart 时旧 Surface 自动失效；
- stale callback 无法重新 show 旧 Surface；
- candidate Runtime 失败可自动 rollback；
- network offline + active image 正常启动；
- offline import 可用；
- active/previous layer 不被 GC；
- UI 无跨资源 procedure；
- hidden main 为 0。

# 4. Round 4：Capability + Native Gateway + Shell v2 + CLI + Plugin Integration

## 4.1 目标

建立最终对外能力层，并吸收参考项目真正有价值的桌面体验。

## 4.2 Protocol Codegen

单一 schema 生成：

- Rust protocol types；
- TypeScript host-sdk；
- Shell command types；
- capability enum/table；
- JSON schemas；
- docs command table；
- compatibility fixtures。

CI 禁止 drift。

## 4.3 Capability Broker

授权输入：

```text
subject
surface
origin
runtimeGeneration
capability
hostMode
```

Shell 不再携带静态手写 capabilities map。

## 4.4 Shell v2

Shell 只做：

- titlebar/window controls；
- reload；
- runtime restart；
- safe mode；
- Gateway entry；
- Diagnostics entry；
- update entry；
- quit。

Shell 不做：

- Runtime lifecycle；
- 下载；
- Plugin Recovery procedure；
- Gateway state machine。

Shell injection 失败：恢复 native decorations。

## 4.5 Native Gateway

删除 Node Gateway sidecar 主路径。

GatewayActor owns：

```text
listener
RuntimeLease
pair tickets
sessions
revocation state
rate limiter
```

不再存在供 UI 使用的 local bearer admin API。

## 4.6 Mobile

Android/iOS：

```text
HTTPS Gateway only
```

移动端不获得 desktop Runtime/native capability。

Android 继续 unsigned-compatible candidate，除非发布政策另行改变。

iOS 可以保持 Simulator Remote 模式。

## 4.7 CLI Shim

借鉴参考项目 CLI integration：

```text
dsh shim
 -> active Runtime image
 -> managed Node
 -> active dsh
```

要求：

- 不改 shell rc 正文；
- 可逆 PATH/shim；
- uninstall cleanup；
- GUI/CLI runtime 版本一致；
- CLI 可以输出 repair 指引。

## 4.8 Plugin Integration

### Host-required

进入 immutable Integration Layer。

不做 mutable auto-heal。

### User/community

仍在 DSH_HOME。

Host 只做：

- observe；
- quarantine；
- safe mode；
- open management surface/plugin。

### Preset Catalog

可以签名 manifest 驱动推荐，但默认安装 0 个第三方插件。

## 4.9 借鉴的 Native 体验

统一通过 Host Protocol：

- notification；
- clipboard；
- open external；
- new window routing；
- zoom；
- tray；
- menu；
- autostart；
- window state restore；
- CLI link；
- runtime version view。

这些能力不能扩散成几十个无边界 command。

## 4.10 Round 4 验收

- capability 单一事实源；
- Shell/SDK/docs 无 drift；
- remote page 不能获得 desktop capability；
- Gateway 不再需要 Node admin sidecar；
- Gateway lease invalid 后停止代理；
- CLI/GUI active Runtime 一致；
- Host-required integration 可由 layer digest 验证；
- community plugin 不进入 Host bundle。

# 5. Round 5：可证明架构 + 体积/性能 + Release Graph + 全清理

## 5.1 目标

最后一轮不是“再修几个 bug”，而是证明新系统满足不变量，并删除全部过渡结构。

## 5.2 Model Test

建立纯模型：

```text
Intent -> model transition -> invariants
```

随机生成：

- EnsureRuntime；
- InstallRuntimeImage；
- RestartRuntime；
- StopRuntime；
- EnsureHarnessVisible；
- EnableGateway；
- DisableGateway；
- InstallHostUpdate；
- Quit。

不变量：

```text
<= 1 Runtime owner
active image always verified
Visible Harness -> valid lease
Ready Gateway -> valid lease
stale lease cannot mutate current resources
failed download never changes active
Quit -> zero resources
```

## 5.3 Property Tests

重点：

- reducer；
- generation monotonic；
- RuntimeLease invalidation；
- manifest parser；
- capability decision；
- layer GC；
- rollback；
- download resume offsets。

## 5.4 Fault Injection

必须覆盖：

### Distribution

- channel signature invalid；
- image signature invalid；
- layer digest mismatch；
- mirror malicious bytes；
- Range server returns 200/206/416；
- download disconnect；
- disk full；
- corrupt archive；
- path traversal；
- decompression bomb；
- quit during download/verify。

### Runtime

- spawn failed；
- wrong PID；
- wrong nonce；
- wrong generation；
- wrong origin；
- crash before ready；
- crash after ready；
- candidate regression。

### Surface

- create failed；
- stale Finished；
- timeout；
- Shell inject failure。

### Gateway

- bind conflict；
- Runtime restart while active；
- session revoke race；
- invalid public origin。

### Update

- download failure；
- signature failure；
- install while Runtime transition；
- quit during updater handoff。

## 5.5 Fake Clock

所有 timeout/backoff/retry 测试使用 fake clock。

CI 不允许靠真实 sleep 等 20/30 秒。

## 5.6 Size SLO

正式 current-head candidate 必须产生：

```text
host-size-report.json
runtime-layer-size-report.json
incremental-update-report.json
```

检查：

- Host artifact budgets；
- integration layer <= 10 MB；
- Runtime Image <= 100 MB compressed；
- duplicate layer bytes；
- incremental update bytes。

若 Runtime 仅 dsh layer 变化，更新流量不得退化成整 Host + Node 重下。

## 5.7 Performance SLO

记录：

```text
warm process -> Harness visible
runtime start -> ready
ready -> Harness visible
restart -> visible
manifest resolve
verify
activation
quit drain
```

首次大下载不设固定绝对时延，但必须：

- progress 持续更新；
- resume 生效；
- throughput 可记录；
- UI 不冻结。

## 5.8 Release Graph

必须把两条发布生命周期连接起来：

```text
Host Release
Runtime Image Release
```

Host Manifest：

```text
hostVersion
sourceCommit
protocolVersion
artifactHashes
trustRootVersion
```

Runtime Manifest：

```text
imageId
sourceCommit
hostProtocolRange
nodeVersion
dshVersion
dshCommit
integrationVersion
layerDigests
signature
```

Release 只消费 exact Candidate Graph。

## 5.9 删除所有过渡代码

最终 grep 必须为 0：

- Electron；
- Host Bridge v1；
- hidden main；
- runtime_starting/restarting/stopping；
- gateway_starting；
- Node Gateway sidecar main path；
- UI lifecycle orchestration；
- full runtime forced into default Host package；
- workspace node_modules bundle；
- duplicated capability lists；
- public token URL。

## 5.10 五轮总审计

至少做：

1. Architecture dependency audit；
2. Lifecycle/model audit；
3. Security/capability audit；
4. Package/runtime distribution audit；
5. User main-path audit；
6. Current-head CI audit；
7. Cross-platform native build audit；
8. Runtime bootstrap/rollback audit；
9. Gateway/mobile audit；
10. Release immutability/provenance audit。

发现全部真实问题后修复并重新跑，直到 current head 全绿。

# 6. 正常用户最终体验

## 首次安装

```text
下载约 6~20 MB Host Installer
 -> 安装
 -> 启动
 -> Bootstrap 下载 Runtime layers
 -> 自动验证
 -> 打开 Harness Web
```

## 后续 Host 更新

只更新小 Host artifact。

## 后续 dsh 更新

只下载变化 Runtime layer；Node 未变化时不重复下载 Node。

## 离线

已有 active Runtime：直接运行。

无 Runtime：导入 Offline Full Bundle / `.hdi`。

## Runtime 更新失败

自动保留/恢复 previous，不影响旧可用版本。

# 7. 五轮完成定义

全部满足才允许认为 v0.2.0 重构完成：

- Host-only 默认安装包；
- package budgets 通过；
- Runtime Layer Store 可用；
- resume/retry/fallback/verify/atomic install 可用；
- active/previous/candidate 可用；
- candidate regression 自动 rollback；
- RuntimeActor/StoreActor/SurfaceActor/GatewayActor 显式状态机；
- RuntimeLease / Reconciler 可用；
- hidden main 删除；
- Host Protocol v2 / Capability Broker 唯一事实源；
- Native Gateway；
- Shell v2；
- CLI shim；
- Integration Layer production-only；
- Model/Property/Fault tests；
- size/performance gates；
- Host/Runtime Release Graph；
- current-head Windows/macOS/Linux/Android/iOS 支持范围全绿；
- 所有旧兼容层和孤儿逻辑删除。

这五轮结束后，HarnessDock v0.2.0 才从“一个能启动 Harness 的桌面壳”升级为真正可长期演进的 **轻量 Native Host + Managed Runtime Platform**。
