# HarnessDock v0.2.0 五轮重构执行计划

> 本文是 `docs/v0.2.0-architecture-five-round-final.md` 的唯一实施计划。  
> 原则：**不兼容旧架构，不建立长期过渡层，不以最小改动为目标，以最终结构正确、状态可证明、发布可验证为目标。**

---

# 0. 五轮总览

```text
Round 1  清空旧边界，建立 Protocol + Kernel + Adapter 骨架
   ↓ 架构审计 / 依赖审计 / 主链审计
Round 2  Resource Actor + 显式状态机 + 唯一资源所有权
   ↓ 并发审计 / 取消审计 / 进程泄漏审计
Round 3  RuntimeLease + Resource Graph + Desired-State Reconciler + Recovery Policy
   ↓ 跨资源一致性审计 / 故障恢复审计
Round 4  Capability Broker + Protocol Codegen + Native Gateway + Security Contract
   ↓ 权限审计 / 密钥审计 / 远程边界审计
Round 5  Model/Property/Fault Test + Performance + Release Graph + 全面清理
   ↓ 五轮总审计 / current-head 全量 CI / candidate / release invariant
```

每一轮都必须执行五类检查：

1. **结构检查**：模块依赖是否出现反向调用、God Object、共享所有权；
2. **状态检查**：是否存在非法状态组合、stale callback、取消后发布资源；
3. **安全检查**：origin、token、capability、secret 是否越界；
4. **用户主链检查**：正常启动必须直接进入 Harness Web，可选功能失败不能阻断；
5. **测试/发布检查**：本轮新增不变量必须有永久自动化门禁。

每轮发现的问题必须在本轮清零，不允许写成“后续再修”的已知核心断链。

# 1. Round 1：架构清场 + Protocol/Kernel 骨架

## 1.1 目标

把当前“模块互相直接调用”的宿主改造成：

```text
Tauri Adapter
  -> Host Protocol v2
  -> Host Kernel
```

这一轮不急于把所有 Runtime/Gateway 细节重写，但必须切断旧业务入口继续扩散的可能。

## 1.2 必须删除/停止使用

- Host Bridge apiVersion=1；
- 大量独立业务 Tauri command 作为长期 API；
- Tray/Menu/Shell 到 Runtime/Gateway 模块的直接调用；
- 隐藏 `main` 控制页承担正常启动；
- Electron runtime/update/release/test 残留；
- 旧配置 schema 作为新架构依赖；
- 历史 `lifecycle.rs` 作为最终状态真相。

允许暂时保留旧 Runtime/Gateway 内部实现，但只能被新的 Kernel/Adapter 封装调用，不能继续暴露新 API。

## 1.3 新建 crate

```text
crates/host-protocol
crates/host-core
crates/host-testkit
```

Round 1 最低实现：

### host-protocol

- `HostCommand`
- `HostResponse`
- `HostEvent`
- `HostError`
- `HostSnapshot`
- `Capability`
- `ProtocolVersion`

### host-core

- `HostKernel`
- `HostIntent`
- `EventBus`
- `SettingsV2`
- 初版 `KernelSnapshot`

### host-testkit

- fake clock
- fake process launcher
- fake event sink

## 1.4 Tauri Adapter

把 desktop-specific 代码移动到：

```text
adapter/app.rs
adapter/ipc.rs
adapter/window.rs
adapter/tray.rs
adapter/menu.rs
adapter/mobile.rs
```

`lib.rs` 最终限制：

```text
create kernel
register adapters
register host_dispatch
forward run events
shutdown
```

## 1.5 IPC 收敛

业务侧只注册：

```text
host_dispatch
host_snapshot
host_subscribe / event bridge
```

窗口最小化/最大化/关闭可以作为原生 primitive 单独保留。

## 1.6 Round 1 验收

必须新增契约测试：

- `lib.rs` 不出现 runtime/gateway 业务分支；
- Tauri handler 不允许再次增加任意业务 command；
- Shell/Menu/Tray 不允许 import/call Runtime implementation；
- Protocol command 使用 enum/tagged payload；
- HostError 公共结构不含 secret field；
- 正常启动仍由 native host 发起。

## 1.7 Round 1 审计后修正

如果发现 Kernel 开始承载具体 stop/start 顺序，立即阻止：Round 1 Kernel 只能接受 intent/dispatch，不能成为新 Workflow God Object。

# 2. Round 2：Resource Actor + 唯一资源所有权

## 2.1 目标

彻底删除“多个 bool + Mutex<Option<Resource>>”生命周期模型。

建立：

```text
RuntimeActor
SurfaceActor
UpdateActor
```

Gateway 可以先建立 Actor 接口，Native Gateway 实现在 Round 4 完成。

## 2.2 Actor 公共规则

每个 Actor：

- 单 mailbox；
- 自己持有资源；
- 命令串行；
- 显式状态 enum；
- generation；
- cancellation token；
- typed event；
- snapshot watch；
- shutdown 必须幂等。

禁止 Actor 直接持有其他 Actor 的内部锁或资源句柄。

## 2.3 RuntimeActor

状态：

```text
Stopped
Preparing
Starting
Probing
Ready
Degraded
Stopping
Cancelling
Failed
```

删除：

- runtime_starting；
- runtime_restarting；
- runtime_stopping；
- RestartGuard/StopGuard/StartGuard 风格多原子门禁。

Restart 改为：

```text
new desired generation
 -> cancel/stop current generation
 -> launch next generation
```

## 2.4 Process Ownership

Windows：

- Job Object；
- Actor 独占 process + job handle；
- Job close 清整棵子树。

Unix：

- process group；
- TERM -> deadline -> KILL。

必须删除“正常退出靠全局 PID 扫描”的设计。

## 2.5 ready.v2 handshake

新增：

```text
schemaVersion
generation
nonce
pid
host
port
dshVersion
url
```

必须验证：

- nonce；
- generation；
- PID；
- exact 127.0.0.1；
- exact port；
- exact origin；
- username/password absent。

## 2.6 SurfaceActor

先建立 HarnessSurface 状态机：

```text
Absent
Creating
Loading
Visible
Hidden
Closing
Failed
```

每次 navigation 有 `navigation_id`。

`Finished/Failed` 必须匹配 generation + navigation_id。

## 2.7 UpdateActor

把 update check/install 从普通函数提升为事务状态：

```text
Idle
Checking
CandidateReady
PreparingInstall
Installing
RestartRequested
Failed
```

## 2.8 Round 2 验收

必须证明：

- 任意时刻最多一个 owned Runtime；
- startup cancel 后不允许 late child publish；
- stale ready 文件不能激活新状态；
- stale WebView callback 不改变新 navigation；
- shutdown 重复调用结果一致；
- Windows/macOS/Linux actor 单测和 Rust check 全绿。

## 2.9 Round 2 审计后修正

如果 Actor 之间开始互相直接 `.send().await` 形成业务编排链，停止扩展；跨 Actor 依赖必须进入 Round 3 的 Resource Graph/Reconciler。

# 3. Round 3：RuntimeLease + Resource Graph + Reconciler + Policy

## 3.1 目标

解决 Actor 有了以后仍可能存在的“手工编排顺序”问题。

建立：

```text
Desired State
Resource Graph
RuntimeLease
Reconciler
Recovery Policy Engine
```

## 3.2 RuntimeLease

```text
RuntimeLease {
  generation,
  runtime_id,
  pid,
  origin,
  private_app_url,
  dsh_version,
}
```

规则：

- private_app_url 不进入 public snapshot；
- Surface/Gateway 必须使用 lease；
- generation 改变，旧 lease 立即无效；
- lease 不能跨 Runtime restart 复用。

## 3.3 Desired State

```text
HostDesiredState {
  app,
  runtime,
  harness_surface,
  gateway,
  update,
}
```

UI 只设置 intent，不编排 procedure。

例如“重启 Runtime”：

```text
Intent::RestartRuntime(Normal)
```

而不是：

```text
stop gateway
close window
stop runtime
start runtime
open window
```

## 3.4 Resource Graph

```text
AppSession
  -> Runtime
       -> HarnessSurface
       -> Gateway
  -> Update
  -> Diagnostics
```

必须明确：

- dependency；
- desired condition；
- ready condition；
- teardown order；
- invalidation propagation。

## 3.5 Reconciler

Reconciler：

- 读取 desired snapshot；
- 读取 actor snapshots；
- 计算下一组 action；
- 向 Actor 发 command；
- 等 event 后再次 reconcile。

禁止：

- Reconciler 持有 Child/Window/Socket；
- Reconciler 自己 sleep 等 ready；
- Reconciler 修改 Actor state。

## 3.6 Recovery Policy

把 normal/quarantine/safe/recovery surface 的选择移到纯策略：

```text
Failure -> RecoveryDecision
```

必须有：

- generation 内最大恢复次数；
- 相同故障退避；
- infinite restart loop hard stop；
- confirmed quarantine 优先；
- 最终可见 RecoverySurface。

## 3.7 删除隐藏控制页

Round 3 完成：

- 删除常驻 `main` 控制页；
- RecoverySurface 动态创建；
- GatewaySurface 动态创建；
- DiagnosticsSurface 动态创建。

正常启动时只有 Splash（可选短暂）和 HarnessSurface。

## 3.8 Round 3 验收

场景必须全部自动化：

- cold start -> Harness visible；
- Runtime crash -> lease invalid -> Surface/Gateway 失效；
- restart -> new generation -> new Surface；
- Gateway enabled while Runtime stopped -> reconciler 先启动 Runtime 或明确拒绝，不能形成孤儿 Gateway；
- quit during starting -> 最终所有 actor stopped；
- update install -> 资源按图 teardown。

## 3.9 Round 3 审计后修正

如果 Resource Graph 中出现循环依赖，必须在本轮消除；不能用“优先级 if/else”掩盖环。

# 4. Round 4：Protocol/Capability/Security + Native Gateway

## 4.1 目标

把架构从“内部正确”升级到“外部边界长期稳定且最小权限”。

完成：

- Protocol schema 单一事实源；
- TypeScript Host SDK codegen；
- Capability Registry/Broker；
- Native Gateway v2；
- Shell v2；
- Settings/Secrets v2。

## 4.2 Protocol Codegen

从 Rust schema/IDL 生成：

```text
packages/host-sdk/src/generated.ts
packages/plugin-harness-shell/src/generated-capabilities.ts
docs/generated/host-protocol-v2.md
tests/fixtures/protocol-v2.json
```

CI 必须 `generate -> git diff --exit-code`。

## 4.3 Capability Broker

授权维度：

```text
subject
surface
origin
runtime_generation
capability
```

规则：

- HarnessSurface local exact origin 才能申请 desktop shell capability；
- Recovery/Gateway/Diagnostics 只拿自身需要的权限；
- remote Gateway Harness 默认无 desktop privileged capability；
- Shell UI 根据 capability snapshot 渲染。

## 4.4 Shell v2

删除 Host Bridge v1。

Shell 只依赖 `host-sdk`：

```text
subscribe snapshot
render capability menu
dispatch typed command
```

Shell 失败仍必须 fail-open。

## 4.5 Native Gateway

删除 Node sidecar 主路径和 local bearer admin API。

GatewayActor 直接 owns：

- listener；
- pairing tickets；
- sessions；
- revocations；
- runtime lease；
- rate limiter。

Gateway 管理命令直接经 Host Protocol 到 Actor。

## 4.6 Secrets

普通 settings 与 secret store 分离。

禁止：

- admin token 写 ready file；
- session secret 出现在 diagnostics；
- pairing token 在 UI 日志中打印；
- private Runtime URL 出现在 public snapshot。

## 4.7 Security Tests

必须覆盖：

- localhost/IPv6/127.0.0.2 不被当作 managed exact origin；
- cross-origin navigation 被拒绝；
- stale runtime generation capability 被拒绝；
- remote surface 请求 desktop capability 被拒绝；
- gateway connect URL token 只能单次消费；
- revoke 后 session 立即失效；
- public diagnostic 全路径脱敏。

## 4.8 Round 4 验收

- command/capability 只有一份 schema source；
- Shell/SDK/docs 无手工漂移；
- Gateway 无 Node sidecar 依赖；
- Gateway 启停不依赖 local admin bearer token；
- secret scan + tests 全绿。

# 5. Round 5：可证明正确性 + 性能 + Release Graph + 最终清理

## 5.1 目标

不是“再跑一遍测试”，而是证明新架构具备长期演进能力。

完成：

- model test；
- property test；
- fault injection；
- deterministic time；
- performance SLO；
- resource leak gate；
- build/release graph；
- 文档与旧代码最终清场。

## 5.2 Host Testkit

提供：

```text
FakeClock
FakeRuntimeProcess
FakeGatewayTransport
FakeSurface
FaultInjector
ModelKernel
ScenarioRunner
```

## 5.3 Model/Property Test

随机 intent 序列：

```text
Start
Restart
SafeRestart
EnableGateway
DisableGateway
HideSurface
ShowSurface
CheckUpdate
InstallUpdate
Quit
```

验证真实 actor snapshots 与 model state 一致。

必须长期守住的不变量：

1. 最多一个 Runtime owner；
2. stopped Runtime 没有有效 lease；
3. Visible Surface 必须拥有当前 generation lease；
4. Ready Gateway 必须拥有当前 generation lease；
5. stale event 不得改变当前 generation；
6. Quit 必须收敛到零 owned resources；
7. InstallUpdate 时 Runtime/Gateway 不运行；
8. public snapshot 不含 secret；
9. capability grant 必须可追溯到 registry policy；
10. recovery 有硬上限。

## 5.4 Fault Injection Matrix

至少覆盖：

- spawn 失败；
- spawn 后 cancel；
- ready partial write；
- ready schema mismatch；
- nonce mismatch；
- PID mismatch；
- Runtime immediately exits after ready；
- Child stop timeout；
- Job/process-group cleanup failure；
- stale WebView callback；
- Shell injection failure；
- Gateway bind conflict；
- pairing during Runtime restart；
- Runtime crash during active Gateway session；
- update during restart；
- settings atomic rename failure；
- event subscriber lag/drop。

每个故障必须有明确最终收敛状态。

## 5.5 Deterministic Time

所有 timeout/retry/backoff 使用 Clock trait。

测试禁止依赖大量真实 `sleep`。

## 5.6 性能门禁

建立 startup trace v2：

```text
kernel_created
runtime_commanded
runtime_spawned
runtime_ready
surface_created
surface_navigation_started
surface_visible
```

不记录 URL/token/error 原文。

建议 gate：

- Host controlled spawn overhead P95 < 500ms；
- ready -> WebView request P95 < 150ms；
- window primitive P95 < 50ms；
- shutdown coordinator overhead P95 < 2s；
- leaked managed child = 0。

## 5.7 Build Manifest / Release Graph

生成 `build-manifest.json`：

```text
clientVersion
sourceCommit
protocolSchemaDigest
runtimeImageDigest
shellPackageDigest
gatewayBuildDigest
tauriConfigDigest
platform
arch
```

Candidate 与 Release 都必须读取并验证同一 manifest。

发布 gate：

- current main SHA；
- ci green；
- tauri-ci green；
- upstream-compat green；
- candidate green；
- candidate source SHA == release SHA；
- manifest digests 一致；
- no tag force move；
- no asset clobber；
- SHA256SUMS；
- SBOM/provenance 建议 mandatory。

## 5.8 最终代码清理

必须删除：

- Host Bridge v1；
- hidden main control page；
- old lifecycle flag model；
- old gateway sidecar 主路径；
- old direct Tauri business commands；
- Electron source/workflow/test；
- temporary migration adapter；
- duplicate capability tables；
- obsolete parity tests that assert旧实现文本而非新不变量；
- 旧方案作为 current docs 的索引入口。

历史文档可留在 Git 历史；仓库当前 docs 索引只指向五轮架构基线。

# 6. 每轮固定审计清单

每轮完成前至少检查以下项目：

## A. Dependency Graph

- 是否有 adapter -> internal implementation 越层；
- actor 是否互相获取内部锁；
- 是否出现 crate 环依赖；
- Kernel/Reconciler 是否开始持有真实资源。

## B. Lifecycle

- 是否存在 boolean lifecycle state；
- cancellation 是否能阻止 late publish；
- stale generation 是否能修改当前 state；
- quit 是否一定收敛。

## C. Security

- exact origin；
- capability 最小权限；
- secret boundary；
- public snapshot redaction；
- remote/local surface privilege separation。

## D. User Journey

- 启动 -> Harness Web；
- Shell 坏 -> Harness 仍可用；
- Tray 坏 -> Harness 仍可用；
- Gateway 坏 -> Harness 仍可用；
- Update 坏 -> Harness 仍可用；
- Runtime 坏 -> Recovery 明确可见；
- 无 tray 退出路径完整。

## E. Release

- version contract；
- build determinism；
- source SHA binding；
- artifact integrity；
- platform package smoke。

# 7. 五轮连续执行原则

后续真正开发时，每轮按照以下闭环执行：

```text
implement
 -> format/lint
 -> unit/model/property tests
 -> Rust check/test
 -> JS/TS tests
 -> architecture contract tests
 -> native smoke
 -> security scan
 -> current-head CI
 -> review failures
 -> fix every real failure
 -> rerun until green
 -> only then next round
```

严禁：

- 用旧 head 的 green 证明新 head；
- 因测试过时而把旧结构加回来；
- 为了兼容历史 API 保留双路径；
- 用“临时 bool”恢复生命周期；
- 让 UI 再次承担 orchestration；
- 以 runner/config 失败冒充代码失败；
- 在本轮带着已知主链断链进入下一轮。

# 9. 五轮结束后的唯一架构

```text
                           Tauri Adapter
                                |
                       Host Protocol v2
                                |
                         Capability Broker
                                |
                            Host Kernel
                                |
                    Desired State / Event Bus
                                |
                          Reconciler + Policy
                                |
               +----------------+----------------+
               |                |                |
          RuntimeActor      SurfaceActor      UpdateActor
               |
          RuntimeLease
               |
          GatewayActor

      Diagnostics <- typed snapshots + bounded journal
      Shell       <- host-sdk + capability snapshot
      Mobile      <- HTTPS Gateway only
```

这不是“参考项目架构的复制”，而是以 HarnessDock 的产品目标重新定义的 Native Host Kernel。

# 10. 完成定义

五轮全部完成后，才允许把 v0.2.0 定义为架构完成：

- 旧 Host 生命周期被删除而不是包裹；
- 旧 IPC 被删除而不是长期兼容；
- 旧控制页被删除而不是继续隐藏；
- Resource Actor 是唯一 ownership；
- RuntimeLease 是唯一 Runtime 依赖凭据；
- Reconciler 是唯一跨资源收敛机制；
- Policy 是唯一恢复决策机制；
- Capability Broker 是唯一权限判定机制；
- Protocol schema 是唯一 API 真相；
- Native Gateway 是默认 Gateway；
- Model/Property/Fault Test 守住状态不变量；
- Build Manifest 守住候选与 Release 闭包；
- 当前 head 全量 CI 和平台 smoke 全绿；
- docs 索引不再指向三轮或更早方案作为执行基线。
