# HarnessDock v0.2.0 五轮重构执行计划

> 本文是 `docs/v0.2.0-architecture-five-round-final.md` 的唯一实施计划。  
> 最终分发要求：**桌面安装包内置 Node + dsh，首次启动零 Runtime 下载。**  
> 原则：不兼容旧 Host 架构，不建立长期过渡层；以结构正确、离线可启动、Runtime 足够紧凑、状态可证明、发布可验证为目标。

参考项目事实分析：`docs/reference/deepseek-harness-desktop-size-and-feature-analysis.md`。

---

# 0. 五轮总览

```text
Round 1
Protocol + Adapter + Kernel boundary + Embedded Full Runtime contract
  ↓
Round 2
RuntimeActor + Immutable Runtime Image + aggressive safe pruning
  ↓
Round 3
RuntimeLease + Resource Graph + Reconciler + Surface/Recovery
  ↓
Round 4
Capability Broker + Native Gateway + Shell v2 + CLI/Profile/Plugin integration
  ↓
Round 5
Model/Fault Tests + Performance/Size SLO + Release Graph + Final Cleanup
```

每轮必须执行：

1. 代码建设；
2. 删除本轮已经取代的旧机制；
3. 结构/依赖审计；
4. 状态/并发/取消审计；
5. 安全/secret/origin 审计；
6. 用户主链审计；
7. embedded Runtime/安装包体积审计；
8. 自动化门禁；
9. 修复全部真实问题；
10. 当前 head 验证后再进入下一轮。

禁止把已发现的主链断链留成“后续再修”。

# 1. Round 1：Protocol / Adapter / Embedded Runtime Contract

## 1.1 目标

建立最终边界，同时保证现有 Full Runtime 分发不被错误改成首启下载：

```text
Tauri Adapter
  -> Host Protocol v2
  -> Host Kernel boundary
  -> existing Runtime implementation (temporary)
```

正式 Candidate：

```text
prepare exact dsh source packs
 -> build target Full Runtime
 -> prune Runtime
 -> smoke Runtime
 -> copy to src-tauri/resources/dsh-runtime
 -> Tauri package
```

## 1.2 必须清理

- 缺文件的 `mod bridge / mod desktop / mod service` 半成品；
- Menu/Tray 各自直接编排 Runtime procedure；
- 新代码继续向 `lib.rs` 塞业务逻辑；
- “Host-only installer / first-run Node+dsh download” 文档与契约；
- Electron 相关运行/测试/发布逻辑。

## 1.3 建设项

### A. Desktop Adapter

`desktop.rs` 统一持有：

- Tauri setup；
- menu event adapter；
- run event adapter；
- optional tray/updater fail-open setup。

### B. IPC Adapter

`bridge.rs` 仅负责 Tauri command 注册。Round 1 允许旧 command 仍存在，但不允许再新增另一套业务入口。

### C. Host Protocol v2 初始模型

先定义：

```text
HOST_PROTOCOL_VERSION = 2
HostCommand
CommandEnvelope
HostResponse
ResponseEnvelope
HostError
HostSnapshot
Capability
SubjectKind
RuntimePhase
```

Menu/Tray 立即改为消费 HostCommand。

### D. Embedded Runtime Contract

永久检查：

- `tauri.conf.json` 打包 `resources/`；
- candidate 准备 per-platform Runtime；
- candidate 下载 prepared-runtime 到 `resources/dsh-runtime`；
- candidate 在 Tauri build 前 smoke；
- Rust Runtime 从 application resource 解析 `dsh-runtime`；
- `bundle-runtime` 执行 dsh prune + Node prune；
- native startup 不包含 first-run Node/dsh download。

## 1.4 Round 1 验收

- `pnpm test` 三 OS；
- `pnpm check:embedded-runtime`；
- cargo fmt；
- `cargo check --locked`；
- `cargo test --locked --lib`；
- `ci / tauri-ci / upstream-compat` 当前 head 全绿；
- 安装包仍是 Full-only。

# 2. Round 2：RuntimeActor + Compact Immutable Runtime Image

## 2.1 目标

把 Runtime 从“Mutex + 多 AtomicBool + procedure”改成唯一 owner Actor，同时继续从安装包资源启动。

## 2.2 RuntimeActor 状态

```text
Stopped
Preparing
Starting
Probing
Ready
Degraded
Stopping
Cancelling
Failed
```

删除最终状态真相：

```text
runtime_starting
runtime_restarting
runtime_stopping
```

Restart 是新的 desired generation，不是 bool。

## 2.3 进程 ownership

Windows：

- Job Object；
- KILL_ON_JOB_CLOSE；
- RuntimeActor owns Process + Job。

Unix：

- process group；
- TERM -> grace -> KILL。

PID 扫描只允许 diagnostics/repair。

## 2.4 Runtime Image

Runtime 必须不可变：

```text
dsh-runtime/
  manifest.json
  node.exe | bin/node
  LICENSE
  node_modules/...
```

### Node pruning

正式 Runtime 不需要 Node 官方发行包的开发工具：

- npm/npx/corepack；
- headers；
- man/docs；
- install helper；
- README/CHANGELOG。

必须保留：Node binary + LICENSE。

### dsh pruning

继续并增强：

- production closure only；
- target native only；
- wrong platform/arch pruning；
- dev maps/types/tests/examples/docs pruning；
- license/notice retention；
- prune 后 integrity + smoke。

## 2.5 Runtime size breakdown

Candidate 输出：

```text
nodeBytes
dshBytes
nativeAddonBytes
integrationBytes
prunedBytes
runtimeTotalBytes
```

新增 Runtime payload budget，但第一轮先基于真实 candidate 建基线，再逐步收紧。

## 2.6 Round 2 故障测试

- missing node；
- missing dsh entry；
- wrong native addon；
- malformed manifest；
- process crashes before ready；
- stale ready file；
- cancellation during start；
- stop during probing；
- plugin route crash -> quarantine。

# 3. Round 3：RuntimeLease + Reconciler + Surface

## 3.1 Runtime generation

每次启动生成：

```text
RuntimeGeneration {
  id,
  nonce,
  image_identity,
  mode,
}
```

ready handshake 绑定：

- generation；
- nonce；
- owned pid；
- 127.0.0.1；
- ephemeral port；
- exact origin；
- pinned dsh identity。

## 3.2 RuntimeLease

Surface/Gateway 不保存裸 URL，而使用 generation-bound lease。

Runtime restart 后旧 lease 全部失效。

## 3.3 Desired State

```text
HostDesiredState {
  app,
  runtime,
  harnessSurface,
  gateway,
  update,
}
```

UI 只发 intent，Reconciler 决定 procedure。

## 3.4 SurfaceActor

Surface：

- HarnessSurface；
- RecoverySurface；
- DiagnosticsSurface；
- GatewaySurface；
- SplashSurface。

删除常驻 hidden control page。

Harness load callback 必须校验：

```text
runtime generation + navigation id
```

stale callback 直接丢弃。

## 3.5 Recovery Policy

顺序：

```text
Normal embedded runtime
 -> plugin quarantine
 -> safe profile
 -> RecoverySurface
```

**Recovery 不允许下载另一份 Node/dsh。**

# 4. Round 4：Capability / Gateway / Shell / CLI / Plugin

## 4.1 Capability Broker

授权输入：

```text
subject
surface
origin
runtime_generation
capability
```

输出 Allow/Deny(reason)。

远程页面 capability 固定最小集，绝不因为 URL 看起来是 Harness 就继承 desktop IPC。

## 4.2 Protocol Codegen

单一 schema source 生成：

- Rust/TS command types；
- capability registry；
- Shell SDK types；
- docs command table；
- fixtures。

删除手写重复 command/capability 清单。

## 4.3 Native Gateway

将默认 Node Gateway sidecar 替换为 Rust GatewayActor：

- listener ownership；
- one-time pairing ticket；
- HttpOnly/Secure session；
- revoke；
- RuntimeLease binding；
- rate limit；
- no local bearer admin API。

## 4.4 Shell v2

Shell 继续独立发布，但只消费 Host SDK/Capability snapshot。

Shell injection 失败：

```text
native decorations = true
Harness Web continues
```

## 4.5 Bundled dsh CLI

借鉴参考项目 CLI 体验：安装 HarnessDock 后可选注册 `dsh` shim。

shim 指向安装包内置：

```text
<resource>/dsh-runtime/node
<resource>/dsh-runtime/node_modules/@deepseek-ai/dsh/lib/bin.js
```

不复制 Runtime，不下载 Runtime；卸载清理 shim。

## 4.6 Plugin/Profile

提供 Host entry，不重写 Harness UI：

- plugin status/error；
- add/remove/update 入口；
- quarantine；
- profile list/switch；
- recommended catalog。

社区插件不并入 Runtime，Host 必需 integration 才允许进入 production bundle。

# 5. Round 5：Verification / Performance / Size / Release

## 5.1 Model/Property tests

随机 intent sequence 至少覆盖：

- Start/Stop/Restart；
- Refresh；
- SafeMode；
- Gateway enable/disable；
- Update；
- Quit。

永久不变量：

1. 最多一个 Runtime owner；
2. Ready 必须有 valid lease；
3. stale generation 不影响 current；
4. Gateway Ready 必须持 current lease；
5. Quit 最终没有 child/listener/window transition；
6. 首启正常路径没有 Node/dsh download state。

## 5.2 Fault injection

至少：

- child crash；
- invalid ready nonce；
- wrong origin；
- stale WebView Finished；
- Gateway bind conflict；
- Shell injection failure；
- updater restart race；
- tray/menu failure；
- packaged Runtime file missing。

## 5.3 性能

启动 trace 最终包含：

```text
process_started
runtime_verified
runtime_spawned
runtime_ready
webview_requested
primary_visible
shell_ready | native_fallback
```

核心 SLO：首次安装后首次启动与后续启动都不等待 Runtime 网络下载。

## 5.4 体积门禁

第一阶段上限：

```text
NSIS <= 150 MB
MSI <= 170 MB
DMG <= 180 MB
DEB <= 160 MB
AppImage <= 190 MB
```

再根据 Round 2/3 candidate 数据收紧。

## 5.5 Release Graph

同一 Candidate SHA 产生：

```text
source SHA
 -> exact embedded runtime manifest
 -> platform packages
 -> updater signatures
 -> SHA256SUMS
 -> release tag
```

Release 必须验证：

- tag exact SHA；
- candidate exact SHA；
- runtime manifest exact dsh pin；
- assets non-empty；
- existing asset immutable；
- updater manifest version/digest/signature 一致。

# 7. 完成定义

v0.2.0 五轮完成必须同时满足：

- 安装包内置 Node+dsh；
- 首启不下载 Node/dsh；
- 断网可启动 Harness Web；
- Tauri-only；
- no permanent hidden control UI；
- no multi-AtomicBool lifecycle truth；
- Resource Actor unique ownership；
- RuntimeLease generation correctness；
- Native Gateway；
- generated protocol/capability contract；
- deterministic recovery；
- package/runtime size gate；
- current-head `ci / tauri-ci / upstream-compat` green；
- merge 后 exact-main-SHA candidate green 才允许 release。
