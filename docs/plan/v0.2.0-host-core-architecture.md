# HarnessDock v0.2.0 Host Core Architecture

## Positioning

HarnessDock is a Tauri Host for DeepSeek Harness, not another Harness UI. The official Harness Web remains the primary product surface; native code owns Runtime, Gateway, process supervision, windowing, update integrity and fail-open recovery.

## Architecture after this upgrade

```text
Tauri composition root (lib.rs)
  |
  +-- state.rs
  |    +-- process ownership references
  |    +-- operation admission flags
  |
  +-- lifecycle.rs
  |    +-- typed Runtime/Gateway/Web lifecycle read model
  |    +-- lifecycle invariant detection
  |
  +-- supervisor.rs
  |    +-- cross-service shutdown ordering
  |    +-- startup-child cancellation
  |    +-- graceful exit/restart drain
  |
  +-- startup.rs
  |    +-- native Runtime -> Harness Web coordinator
  |    +-- recovery fallback
  |
  +-- startup_trace.rs
  |    +-- local phase-only performance telemetry
  |    +-- no URL/token/error payloads
  |
  +-- runtime.rs
  |    +-- bundled Node + pinned dsh Runtime
  |    +-- ready.json validation
  |    +-- plugin quarantine / safe profile
  |
  +-- gateway_host.rs
  |    +-- authenticated Gateway sidecar ownership
  |    +-- pairing/revoke lifecycle
  |
  +-- harness_window.rs
  |    +-- exact managed Runtime WebView
  |    +-- Shell fail-open / native titlebar fallback
  |
  +-- update.rs
       +-- signed desktop updater
       +-- immutable release identity
```

## What changed

### 1. Composition root no longer owns lifecycle state

`lib.rs` is reduced to Tauri assembly, menu wiring and event routing. `AppState` moves to `state.rs`, which prevents the composition root from becoming a second Runtime/Gateway implementation.

### 2. Typed lifecycle read model

`lifecycle.rs` normalizes low-level admission flags into explicit Runtime/Gateway/Web phases. Runtime restart intentionally owns nested stop/start phases and is represented as one `Restarting` phase. Impossible overlaps remain detectable as lifecycle violations.

This is intentionally a read-model first architecture: Runtime and Gateway modules continue to own transition guards that are already heavily tested, while every cross-service coordinator consumes one canonical phase interpretation.

### 3. Unified process Supervisor

`supervisor.rs` becomes the only cross-service shutdown coordinator. Exit and updater restart now drain all admitted Runtime/Gateway lifecycle operations, not only child-start tasks. Shutdown order remains:

```text
block new work (quitting=true)
 -> cancel registered starting children
 -> stop Gateway
 -> stop Runtime
 -> wait for Runtime/Gateway lifecycle admissions to become idle
 -> final idempotent stop pass
 -> exit/restart Tauri
```

This closes the remaining class of exit-vs-restart/stop races without changing Runtime startup semantics.

### 4. Native startup observability

`startup_trace.rs` records only phase names plus elapsed milliseconds into private local startup logs:

```text
process_started
runtime_start
runtime_ready
webview_requested
recovery
```

No Runtime URL, launch token, Gateway token, authorization header, error text or user data is written. Trace failures are ignored so observability can never block startup.

`scripts/perf-report.mjs` now consumes these native traces instead of stale Electron-era boot markers.

### 5. Architecture contracts

Parity tests now lock the module boundaries, Supervisor ownership and startup trace format. Future refactors must keep temporary migration workflows out of the repository and must not move lifecycle ownership back into `lib.rs`.

## Core invariants

1. Harness Web remains mandatory; Shell/tray/menu/updater/Gateway remain optional.
2. Desktop Runtime origin is exactly `http://127.0.0.1:<ephemeral-port>`.
3. Gateway can never outlive the Runtime upstream it was created for.
4. Runtime/Gateway child processes are always owned by native state and drained before exit/restart.
5. Recovery never rewrites the user's real `DSH_HOME`.
6. Remote Gateway/mobile pages never receive local privileged Tauri IPC.
7. Android remains unsigned-compatible in GitHub candidate publication; no keystore gate is introduced.
8. Release tag identity and existing signed assets are immutable.

## Further architectural upgrades worth considering after v0.2.0

These are not required to stabilize v0.2.0 and should be treated as later compatibility-breaking work:

- Replace Runtime's internal start/restart/stop admission booleans with one transactional reducer/actor while keeping the typed lifecycle API unchanged.
- Introduce a versioned internal `HostService` trait so Runtime/Gateway/update implementations can be swapped in tests without Tauri handles.
- Move public command errors from strings to a versioned `{ code, scope, message, recovery }` contract.
- Add a primary-visible startup phase from the WebView finished callback and use it for startup SLOs.
- Add a capability registry generated from native command declarations so Shell package capabilities cannot drift from the Host Bridge.
- Add deterministic fault-injection tests for process crash, Runtime URL rotation, Gateway late publication and updater restart races.

The v0.2.0 architecture deliberately stops before these higher-risk rewrites: the current transition owners are already cross-platform green, while the new state/lifecycle/supervisor boundary gives those later changes a stable seam.
