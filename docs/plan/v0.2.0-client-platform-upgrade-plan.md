# HarnessDock v0.2.0 Client Platform 升级改造总方案

> 状态：**当前执行总纲**
>
> 基线：`main` 已合并 Multi-Host + Local/Remote Runtime 基础架构；Electron 继续作为 Stable/LTS 兼容 Host，Tauri 作为 v0.2.0 正式发布目标，Perry 保留为 Experimental / Native R&D。
>
> 目标版本：`v0.2.0`
>
> 文档定位：本文整合并升级此前 `docs/auto-update-assessment.md`、`docs/upgrade-refactor-plan*.md`、Perry/Mobile 架构文档中的有效结论，作为 v0.2.0 后续开发、测试、CI、打包和发布的主计划。旧文档继续保留作历史/专项参考，但如有冲突，以本文为准。

## 1. 版本目标

v0.2.0 不应被定义为“把 Electron 换成 Tauri”，而应被定义为一次 **客户端平台层重构**：

```text
HarnessDock v0.2.0

                 Shared Client Core
                        |
        +---------------+----------------+
        |               |                |
      Tauri          Electron          Perry
   Default Host        LTS          Experimental
        |               |                |
        +---------------+----------------+
                        |
                 RuntimeProvider
                /              \
       LocalRuntime       RemoteRuntime
            |                  |
           dsh            Harness Gateway
```

核心目标：

1. **Tauri 成为正式默认发布客户端**。
2. **Electron 保留完整构建能力**，作为 LTS / Compatibility / Emergency Fallback。
3. **Perry 保留构建能力**，作为 Experimental / Benchmark / Native UI 研发 Host，不阻塞正式 Release。
4. Host 与 Runtime、更新、文件、安全、网络、诊断、生命周期彻底解耦。
5. Tauri / Electron / Perry 共用同一套 Client Contract、Runtime Contract、Capability Matrix 和 Canonical Runtime Artifact。
6. 不 fork 上游 Harness UI，继续复用官方 `dsh web` 与 `~/.dsh` 数据。
7. v0.2.0 Stable 必须满足本文定义的 **Stable Gate 1–10**。

## 2. 产品和发布策略

### 2.1 Host 定位

| Host | 定位 | Release Gate | 正式 Release Assets | 主要用途 |
| --- | --- | --- | --- | --- |
| Tauri | Default / Next-Gen | 必须通过 | 是 | v0.2.0 默认桌面客户端 |
| Electron | Stable/LTS Compatibility | Compatibility Gate | 默认不公开，保留 Actions/LTS 产物 | 回退、特殊平台兼容、迁移保护 |
| Perry | Experimental | 不阻塞 Stable | 否 | Native UI、极限包体、性能和移动技术实验 |
| VS Code | IDE Client | 独立 Gate | VSIX | IDE 使用场景 |
| Mobile | Remote Runtime Preview | Preview Gate | 不进入 v0.2.0 Stable | iOS/Android 后续版本 |

### 2.2 Runtime Payload 模式

Host 和 Runtime Payload 必须分离：

```text
Host = tauri | electron | perry
Runtime = full | thin | system | remote
Channel = stable | beta | lts | experimental
```

建议：

- **Full**：普通用户默认推荐。安装后可离线首次启动，确定性最高。
- **Thin**：高级用户/开发者。安装包较小，首次运行按 Manifest 下载 Canonical Runtime。
- **System**：开发模式，使用系统已有 dsh/Node；不作为普通用户默认。
- **Remote**：移动端/远程客户端，通过 Harness Gateway 连接 Runtime，不在本机启动 dsh。

### 2.3 v0.2.0 正式发布形态

正式 Release 只公开 Tauri：

```text
Windows
- HarnessDock-Setup-0.2.0-win-x64-full.exe      # 默认推荐
- HarnessDock-Setup-0.2.0-win-x64-thin.exe      # 高级用户

macOS
- HarnessDock-0.2.0-macos-arm64-full.dmg
- HarnessDock-0.2.0-macos-x64-full.dmg
- HarnessDock-0.2.0-macos-arm64-thin.dmg
- HarnessDock-0.2.0-macos-x64-thin.dmg

Linux
- HarnessDock-0.2.0-linux-x64-full.AppImage
- HarnessDock-0.2.0-linux-amd64-full.deb
- 对应 thin 版本
```

暂不把 MSI、RPM、Snap、Flatpak、完整固定 WebView2 离线包放入 v0.2.0 P0；它们进入 Enterprise/P2。

## 3. 架构原则

### 3.1 Contract-first

业务层不得直接依赖：

- `electron.*`
- Tauri `invoke()`
- Perry 专有 API
- 平台原生 Swift/Kotlin/Rust API

统一通过 Client Service Contract：

```text
UI / CLI / Deep Link
        |
     CommandBus
        |
 Client Services
        |
 Host Adapter
        |
Tauri / Electron / Perry / Mobile
```

### 3.2 Capability-first

禁止在业务层大量出现：

```ts
if (isElectron) {}
if (isTauri) {}
if (isPerry) {}
```

改成：

```ts
if (host.capabilities.files.save) {}
if (host.capabilities.app.deepLinks) {}
if (host.capabilities.security.secureStorage) {}
```

### 3.3 Runtime 与 Host 独立版本化

版本拆分：

```text
HarnessDock App Version
0.2.0

Runtime Version
0.1.x / Runtime Layout v4+

Plugin Version
各插件独立 semver
```

Host 更新不要求 Runtime 同时变化，Runtime 更新也不要求重新下载安装整个 Host。

### 3.4 安全默认拒绝

WebView 只拥有最低必要 Native 权限。

尤其 Tauri：

- 不向 Harness WebView 暴露通用 shell/spawn。
- Runtime 启停、安装、更新、密钥、Updater 等高权限能力仅允许 Rust/Trusted Host 层调用。
- 所有 WebView -> Native 调用必须经过窄接口、权限检查和参数校验。

## Gate 1：Client Command Bus + Client Services Contract

### 目标

把 UI、CLI、Deep Link、托盘、Updater 等入口统一到一个 Command Bus，避免每个入口重复实现业务逻辑。

### Command 模型

```ts
export type ClientCommand =
  | { type: 'OPEN_SESSION'; sessionId: string }
  | { type: 'OPEN_WORKSPACE'; path?: string }
  | { type: 'INSTALL_PLUGIN'; pluginId: string; version?: string }
  | { type: 'UPDATE_APP' }
  | { type: 'UPDATE_RUNTIME' }
  | { type: 'RESTART_RUNTIME' }
  | { type: 'EXPORT_DIAGNOSTICS' }
  | { type: 'PAIR_DEVICE'; token?: string }
```

### Client Services

```ts
interface ClientServices {
  app: AppLifecycleService
  runtime: RuntimeService
  files: FileService
  credentials: CredentialService
  updates: UpdateService
  diagnostics: DiagnosticsService
  network: NetworkService
  notifications: NotificationService
  deepLinks: DeepLinkService
  windows: WindowService
  policy: PolicyService
}
```

### 验收

- UI/CLI/Deep Link 能触发同一 Command Handler。
- Command 有 schema validation。
- 高权限 Command 必须有 Policy/Capability 检查。
- 单元测试覆盖 Command routing、错误传播、取消和超时。

## Gate 2：Single Instance + Runtime Lease v2

### 目标

区分“App 单实例”和“Runtime 独占”两种问题。

### App Instance Lock

同一 Host 第二次启动：

```text
第二实例
 -> 检测已有实例
 -> 传递 argv / deep link / file open 请求
 -> 激活已有窗口
 -> 第二实例退出
```

不得把正常第二次点击转化成 Runtime Lease Error。

### Runtime Lease v2

当前 Lease 需从 `DesktopHostKind` 泛化到统一 `HarnessHostId`。

建议记录：

```ts
interface RuntimeLeaseRecordV2 {
  schemaVersion: 2
  token: string
  ownerHost: HarnessHostId
  ownerPid: number
  runtimeId: string
  runtimePid?: number
  endpoint?: string
  dshVersion?: string
  protocolVersion: number
  acquiredAt: string
  updatedAt: string
}
```

### 行为

- 同 Host：Single Instance 优先处理。
- 不同 Host：Runtime Lease 防止多个 Host 同时管理同一个本地 Runtime。
- Owner 异常退出：PID liveness + token 防 ABA + stale recovery。
- Runtime Lease 与 Host userData 隔离；官方 Harness 数据继续使用 `~/.dsh`。

### 验收

- Electron/Tauri 同时启动时不会产生两个 dsh process tree。
- stale lease 自动回收。
- 旧 Lease schema 可安全迁移或忽略重建。
- 测试覆盖并发 acquire、stale owner、token-safe release。

## Gate 3：Tray + Graceful Lifecycle

### 目标

把 HarnessDock 从“一个窗口”升级为“Runtime-aware 桌面客户端”。

### 生命周期状态机

```text
STARTING
 -> RUNTIME_STARTING
 -> READY
 -> HIDDEN_TO_TRAY / ACTIVE
 -> SHUTTING_DOWN
 -> STOPPED
```

### Tray 菜单

```text
Open HarnessDock
----------------
Runtime: Running / Degraded / Stopped
Runtime Version: x.y.z
Restart Runtime
Stop Runtime
----------------
Check Updates
Diagnostics
----------------
Quit
```

### 关闭策略

默认建议：

- 点击窗口 X：可配置为退出或隐藏到托盘；首次切换时给用户清晰设置。
- 真正 Quit：保存 Session Snapshot -> 停止 Runtime -> release lease -> 清理 Gateway -> exit。
- OS shutdown/logout：执行有时间上限的 graceful shutdown，超时后 force cleanup。

### 验收

- 不遗留 dsh/Node 子进程。
- crash/kill 后下次启动能识别旧进程/lease。
- Windows/macOS/Linux 行为一致或有明确平台差异。

## Gate 4：Deep Link + OAuth Callback

### 目标

统一浏览器、Marketplace、OAuth 和设备 Pairing 到客户端。

### URI Scheme

```text
harnessdock://chat/new
harnessdock://session/<id>
harnessdock://workspace/open?... 
harnessdock://plugin/install?id=...
harnessdock://mcp/install?id=...
harnessdock://pair?token=...
harnessdock://auth/callback?...
```

### 安全要求

- URI 参数严格 schema 校验。
- Plugin/MCP 安装不能因为点一个 URI 就绕过 Trust/Deploy Gate。
- Pairing token 必须短期、单次、可撤销。
- OAuth 使用系统浏览器，不在内嵌 WebView 里强制登录。

### 验收

- 冷启动 deep link。
- 已启动时 deep link -> Single Instance 转发。
- OAuth callback 能正确恢复原 Session。
- Windows/macOS/Linux 注册和卸载逻辑正确。

## Gate 5：Native File / Download Service

### 目标

彻底从 WebView 的实现差异中抽离文件能力。

### 统一接口

```ts
interface FileService {
  pickFiles(options?: PickFileOptions): Promise<PickedFile[]>
  pickDirectory(options?: PickDirectoryOptions): Promise<string | null>
  saveFile(options: SaveFileOptions): Promise<SavedFile | null>
  openFile(path: string): Promise<void>
  revealFile(path: string): Promise<void>
  uploadFile(input: UploadFileInput): Promise<UploadResult>
  downloadFile(input: DownloadFileInput): Promise<DownloadResult>
}
```

### 安全要求

- 路径 canonicalize。
- 禁止目录穿越。
- 下载文件名净化。
- 大文件流式传输，不整文件读入内存。
- Workspace 权限边界明确。
- 临时文件有生命周期和清理机制。

### Host 实现

- Tauri：Dialog/FS/Opener/HTTP/Upload Adapter。
- Electron：现有 dialog/download/IPC 适配为统一 Contract。
- Perry：能力不足时通过受控 fallback / Gateway，不伪造 capability。
- Mobile：Native picker + Gateway File API + save/share sheet。

### 验收

至少覆盖：

- `.md/.txt/.json/.zip/.pdf/图片`。
- 中文和 Unicode 文件名。
- >1 GB 大文件不会导致主进程 OOM。
- 下载中断可恢复/重试或给出明确失败。

## Gate 6：Secure Credential Store

### 目标

敏感信息不能继续依赖普通 JSON 明文保存。

### 保存内容

- Gateway device credential。
- Pairing long-lived device key。
- OAuth refresh token（如有）。
- Proxy password。
- Update/private channel credential（如有）。
- 未来 Provider credential 的 Host-side 引用。

### 统一接口

```ts
interface CredentialService {
  get(key: string): Promise<string | null>
  set(key: string, value: string): Promise<void>
  delete(key: string): Promise<void>
  list(prefix?: string): Promise<string[]>
}
```

### Adapter

- Tauri：Stronghold / OS-backed secure storage strategy。
- Electron：OS Credential Store Adapter。
- iOS：Keychain。
- Android：Keystore-backed storage。

### 安全要求

- 日志绝不打印 secret value。
- Diagnostics 自动脱敏。
- 支持 credential rotation/revoke。
- 数据损坏时 fail closed，不静默退回明文。

## Gate 7：Update Manager + Runtime Update Manager

### 目标

形成三层更新：

```text
Host Update
Runtime Update
Plugin Update
```

不能继续把所有升级都绑定到一个大安装包。

### 7.1 Host Update

Tauri 正式客户端使用 Tauri Updater 管理：

```text
CHECKING
 -> AVAILABLE
 -> DOWNLOADING
 -> VERIFYING
 -> READY_TO_INSTALL
 -> INSTALLING
 -> RELAUNCHING
 -> SUCCESS
```

必须支持：

- 自动识别 OS / arch / channel。
- 签名校验。
- 自动下载（可配置）。
- “更新并重启”。
- 更新前 Session Snapshot。
- 更新后自动 relaunch 并恢复。
- 失败记录和人工回退指引。

### 7.2 Runtime Update

Runtime 使用 HarnessDock 自有 Manager，不与 Host Updater 耦合。

目录建议：

```text
~/.harnessdock/runtime/
├── versions/
│   ├── <version-a>/
│   └── <version-b>/
├── current.json
├── previous.json
├── staging/
└── cache/
```

流程：

```text
fetch manifest
 -> compare version/files
 -> download to staging
 -> sha256/signature verify
 -> runtime self-test
 -> stop current runtime
 -> atomic activate pointer
 -> start new runtime
 -> health check
 -> success
       or
 -> rollback previous
```

### 7.3 “增量更新”定义

v0.2.0 采用两级策略：

1. **文件级增量**：只下载 Runtime Manifest 中变化的文件/包。
2. **缓存复用**：内容 hash 不变则复用本地 cache。

Binary diff/bsdiff/courgette 类二进制差分进入 v0.2.x，不作为 v0.2.0 首发 blocker。

### 7.4 更新策略

默认模式：

```text
自动检查
自动后台下载（可配置）
用户选择“更新并重启”
```

可选模式：

- 手动。
- 空闲时自动更新并重启。
- 企业维护窗口（P2）。

### 7.5 自动版本识别

统一 `release-manifest.json`：

```json
{
  "schemaVersion": 2,
  "channel": "stable",
  "appVersion": "0.2.0",
  "minimumAppVersion": "0.2.0",
  "runtime": {
    "version": "0.1.x",
    "protocolVersion": 1,
    "layoutVersion": 4
  },
  "artifacts": []
}
```

Artifact 至少包含：

- host
- runtime mode
- os
- arch
- type
- url
- size
- sha256
- signature
- minimum OS
- recommended

### 验收

- 自动识别正确升级包。
- Full/Thin 不串包。
- stable/beta/lts/experimental channel 不串流。
- Runtime 升级失败自动恢复 previous。
- 更新过程中断电/进程被杀，下次启动能恢复状态。

## Gate 8：Crash Recovery + Session Restore

### 目标

Host crash、Runtime crash、升级重启后，用户能够回到工作上下文。

### Runtime Supervisor 状态

```text
STOPPED
STARTING
READY
DEGRADED
CRASHED
RESTARTING
UPDATING
ROLLING_BACK
```

### 自动恢复策略

- Runtime 单次异常：指数退避自动 restart。
- 短时间连续异常超过阈值：停止自动重启，进入 DEGRADED。
- DEGRADED UI：Restart / Rollback Runtime / Diagnostics。
- 永远禁止无限 crash loop。

### Session Snapshot

保存：

```ts
interface ClientSessionSnapshot {
  schemaVersion: 1
  workspaceId?: string
  sessionId?: string
  route?: string
  windowState?: unknown
  runtimeVersion?: string
  capturedAt: string
}
```

原则：

- 不复制 Harness 自身业务数据；Harness 数据仍以官方持久化为准。
- Snapshot 只保存客户端导航/恢复所需最小上下文。
- 升级前强制 snapshot。
- snapshot schema 可迁移。

### 验收

- Host crash 后重新启动能回到最近 Session/route。
- Runtime crash 不丢 Harness 数据。
- 更新重启后自动恢复。
- snapshot 损坏时安全忽略而非阻塞启动。

## Gate 10：Proxy + Network + WebSocket Recovery

### 目标

让 HarnessDock 在企业网络、代理、VPN、网络切换中可预测运行。

### Network State

```text
ONLINE
OFFLINE
LIMITED
DNS_ERROR
PROXY_ERROR
TLS_ERROR
```

### Proxy Mode

```text
System
Direct
HTTP
HTTPS
SOCKS5
```

支持：

- `NO_PROXY`。
- 自定义 CA（企业场景，严格 opt-in）。
- proxy credential 走 CredentialService。
- 连接 timeout/retry/backoff。

### WebSocket Recovery

```text
CONNECTED

 -> DISCONNECTED
```

要求：

- 页面 reload 不是唯一恢复方案。
- Host sleep/wake、VPN 切换、Wi-Fi 切换可恢复。
- RemoteRuntimeProvider 和 Gateway 使用同一网络状态模型。

### 验收

- 断网后 UI 明确显示离线状态。
- 恢复网络后自动重连。
- Proxy 配置错误可区分 DNS/TLS/Proxy failure。
- 不在日志中泄漏 proxy password。

# 7. Canonical Runtime Artifact

这是 v0.2.0 打包/更新架构的 P0。

当前/历史问题：每个 Host 重新准备自己的 Full Runtime，会造成重复逻辑、重复下载、重复缓存和不同 Host 的构建差异。

目标：

```text
prepare-runtime
      |
Canonical Runtime Artifact
      |
runtime-manifest.json
      |
+-----+---------+--------+
|               |        |
Tauri         Electron  Perry
Full/Thin      LTS      Experimental
```

Runtime 只构建一次，各 Host 只消费。

### Runtime Manifest

建议：

```json
{
  "schemaVersion": 2,
  "runtimeVersion": "...",
  "layoutVersion": 4,
  "protocolVersion": 1,
  "dshVersion": "...",
  "nodeVersion": "...",
  "platform": "windows",
  "arch": "x64",
  "sourceCommit": "...",
  "files": [
    {
      "path": "...",
      "size": 0,
      "sha256": "..."
    }
  ],
  "archive": {
    "url": "...",
    "size": 0,
    "sha256": "...",
    "signature": "..."
  }
}
```

### Full

构建时把 Canonical Runtime 原样嵌入安装包。

### Thin

首次运行下载 **同一个 Canonical Runtime Artifact**。

因此 Full 和 Thin 的 Runtime 内容必须可做 hash equality 验证。

# 8. Tauri Default Host 实现

新增 `apps/tauri`。

建议：

```text
apps/tauri/
├── src/
│   ├── main.ts
│   └── host-adapter.ts
└── src-tauri/
    ├── src/
    │   ├── main.rs
    │   ├── runtime.rs
    │   ├── files.rs
    │   ├── credentials.rs
    │   ├── updater.rs
    │   ├── diagnostics.rs
    │   └── network.rs
    ├── capabilities/
    └── tauri.conf.json
```

运行链路：

```text
Tauri Shell
   |
Rust Runtime Supervisor
   |
Canonical Local Runtime
   |
dsh web --host 127.0.0.1 --port 0 ...
   |
System WebView
   |
Official Harness UI
```

### 安全约束

- Harness WebView 不获得 generic shell spawn。
- Native File、OAuth、Deep Link 等通过窄 Command API。
- Runtime install/update 不暴露给远端网页来源。
- remote-origin capability 默认 deny。

# 9. Electron LTS Adapter 化

不删除 Electron，不进行无收益重写。

重点：

1. 现有 `bootstrapRuntime` 继续工作。
2. 将 Electron 原生功能接到 Client Services Contract。
3. 保持现有 appId / userData / updater 兼容策略，避免破坏老用户。
4. Electron 使用相同 Canonical Runtime Manifest。
5. Electron CI 保留 Windows/macOS/Linux pack，作为 compatibility gate。
6. 正式 Release 默认不再上传 Electron Assets；必要时可生成 LTS fallback release。

# 10. Perry Experimental 收敛

Perry 继续存在，但明确：

- 不阻塞 Tauri Stable Release。
- Capability 必须真实，不用 mock 把 unsupported 标成 supported。
- Desktop Full/Thin 也改为消费 Canonical Runtime，消除 Host-specific Runtime preparation。
- 用作：Native UI、启动速度、RSS、包体 Benchmark。
- 如果未来做不加载官方 Harness WebView 的 HarnessDock Lite，可再次评估 Perry 作为主 Host。

# 11. Update System v2 详细状态机

统一持久化 `update-state.json`，用于崩溃恢复：

```text
IDLE
CHECKING
AVAILABLE
DOWNLOADING
VERIFYING
STAGED
WAITING_FOR_RESTART
STOPPING_RUNTIME
INSTALLING
RELAUNCHING
VALIDATING
SUCCESS
FAILED
ROLLING_BACK
```

建议记录：

```json
{
  "schemaVersion": 1,
  "kind": "host|runtime|plugin",
  "state": "STAGED",
  "fromVersion": "...",
  "toVersion": "...",
  "artifactSha256": "...",
  "createdAt": "...",
  "updatedAt": "...",
  "attempt": 1
}
```

启动时发现非终态：

- 能安全继续 -> resume。
- staged 但未激活 -> verify 后继续。
- installation uncertain -> health validate。
- health fail -> rollback。

必须显式引入：


启动判断：

不得仅通过 semver 猜兼容性。

例如：

```ts
interface RuntimeSession {

  runtimeVersion?: string
  dshVersion?: string

```

11. file open/save/upload/download。

18. runtime update + rollback。

# 16. 性能和体积 Gate

建立持续 Benchmark：

```text
Electron vs Tauri vs Perry
```

记录：

- installer size。
- unpacked size。
- cold start -> window visible。
- cold start -> Runtime ready。
- idle RSS。
- active RSS。
- idle CPU。
- WebView ready time。
- Runtime restart time。

v0.2.0 不要求 Tauri 每项都优于 Electron，但要求：

- 不产生明显启动回归。
- Tauri host payload 显著小于 Electron host payload。
- Full 包新增 Runtime 后仍在预算内。
- 性能数据进入 CI Artifact/Release QA，而不是靠感知判断。

# 17. 代码签名和供应链安全

Stable Release 必须推动：

### Windows

- Authenticode code signing。
- 安装器和 updater artifact 签名。

### macOS

- Developer ID Application。
- Hardened Runtime。
- Notarization + stapling。

### Runtime/Manifest

- SHA-256。
- 签名。
- 明确 source commit / upstream version。
- 下载只允许 HTTPS。
- update manifest 防 downgrade/replay（版本策略 + 签名 + channel）。

### Plugin

继续沿用 Verify / Deploy Gate / Trust metadata，不允许 Deep Link 绕过。

# 23. 风险清单与控制策略

| 风险 | 影响 | 控制 |
| --- | --- | --- |
| 一次拆包过度 | 高 | Contract 先在现有包内稳定，再拆物理 package |
| Tauri remote WebView 权限过大 | 极高 | default deny + narrow commands + capability ACL |
| Runtime 更新中断 | 极高 | staging + immutable versions + atomic pointer + previous rollback |
| Host/Runtime 版本错配 | 高 | protocol/layout/schema version 显式兼容检查 |
| Full/Thin 内容不一致 | 高 | CI hash equality / manifest equality gate |
| Electron 被重构破坏 | 高 | Electron compatibility CI 持续运行 |
| Perry CI 不稳定拖累 Release | 中 | Experimental non-blocking |
| macOS updater/signing | 高 | RC 前真实签名/公证双版本升级测试 |
| Linux WebKitGTK/glibc | 高 | 选择稳定构建基线 + 真发行版 smoke |
| Proxy/企业 CA 复杂 | 中高 | Advanced opt-in + Diagnostics + 不静默降级 TLS |
| Secret 泄露日志 | 极高 | centralized redaction + CI secret fixture tests |

# 25. 推荐的实际开发顺序

为降低风险，代码实施严格按下面顺序推进：

```text
1. Capability Matrix v2
2. Command Bus + Client Services Contract
3. Runtime Lease v2 + App Instance Contract
4. Canonical Runtime Artifact + Runtime Manifest v2
5. Update State / Release Manifest v2
6. Electron Adapter 收敛（作为参考实现）
7. Tauri Host Skeleton + LocalRuntimeProvider
8. Tray/Lifecycle + Deep Link/OAuth
9. Native File + Secure Credential
10. Host/Runtime Update Manager
11. Crash Recovery + Session Restore
12. Logging + Diagnostics
13. Proxy/Network/WebSocket Recovery
14. Tauri Full/Thin pack
15. Signing/Notarization
16. Stable Gate E2E + Release Candidate
```

这一路线的核心原则是：**先把共享 Contract 和 Runtime/Update 地基做稳定，再做 Tauri UI Host；先保证 Electron 不退化，再逐步让 Tauri达到完整 parity；Perry 始终作为 Experimental 适配同一套 Contract，而不是另起一套架构。**
