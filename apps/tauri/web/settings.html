插件诊断

仅在需要排查 Runtime、插件隔离或更新状态时打开；正常使用始终停留在 Harness Web。

Web 优先启动

桌面端验证安装包内置 sealed Runtime 后直接启动本地 dsh 并打开 Harness Web。插件诊断只在用户主动点击后创建。

Runtime 与插件状态

第三方插件失败可进入隔离恢复；正式产品只从安装包资源启动内置 Node+dsh，不使用系统 Node 兜底，也不会在首次启动下载另一份 Runtime。

checking

GitHub 自动更新

远程 Harness Web 不持有安装更新权限。主界面菜单只负责打开这个本地可信诊断面，由 Capability Broker 授权后检查并安装签名有效的稳定 Release。

signed

未配置有效发布签名时不会安装未经验证的程序包。

使用说明

正常使用只需要 Harness Web。Recovery、Gateway、Diagnostics 和 Update 都是按需 Surface，不能成为健康 Harness Web 启动的前置依赖。

on demand

关闭诊断窗口不会停止 Runtime，也不会关闭 Harness Web。退出和更新通过 Host Protocol v2 进入统一 Reconciler/Actor 生命周期。
